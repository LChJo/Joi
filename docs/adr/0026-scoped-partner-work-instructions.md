# ADR 0026：按 Work 整理搭档指令

- 状态：accepted
- 日期：2026-10-10
- 关联：ADR 0007、0017、0025；AC-14/AC-33/AC-46/AC-53

## 决策

Joi 在现有 Wayfinder 推理轮次中合并重复补充、应用用户明确纠正，并记录重要需求变化。每个 Work 使用独立、自包含的指令：目标、相关事实与已有结论、当前有效要求、适用的全局约束、执行边界和交付要求。全局核对搭档获得完整有效需求清单；其他搭档获得其任务需要的内容。逐字核对任务可引用必要原文，作为参考材料标识。不增加独立模型整理调用。

新建和补充 Work 在 application 提交计划前校验非空指令，保持 12,000 字符上限，不静默截断。工具 schema 保持字段可省略，使模型遗漏参数时可由 application 返回明确的校验错误；工具层允许每种工具每轮纠正一次，重复失败结束本轮，不创建用户选择卡或派发事实。

新 brief 在已有 `intent_json` 保存 `briefVersion: 2`，不新增 SQL 列或公开 DTO 字段。交付层同时用于本地、A2A 与任务展示：任务标题、Task instructions、附件引用及验收条件。有效指令存在时不附加累计用户正文；仅无版本且缺有效指令的旧 Work 使用旧原文回退。版本化 brief 缺有效指令或版本不受支持时按配置错误拒绝执行，不回退原文。

`work_resume` 提供包含相关用户回答、当前要求、已确认事实和交付边界的完整替换指令。应用层保留 action/turn 幂等查询；已提交尝试直接复用，不重新改写指令。未提交恢复在同一 SQLite 事务中更新 brief、保留其验收及证据字段、保存新 attempt/outbox；事务失败全部回滚。改派继承已保存的指令；补充 Work 自行提供独立新指令。

## 上下文与兼容

用户原始输入和补充历史仍保留，供主 Joi 理解目标和本地追溯。去除向每个搭档广播的副本不会改变主 Joi 的续接结论背景与 24K/40K/60K 自适应预算。已有权威结果证据、附件、权限和验收逻辑沿用现有机制。历史运行消息不批量重写；新交付使用当前 brief 规则。

模型负责需求的语义整理，机械校验只能保证 brief 存在、长度合规及原文没有被交付层自动附加，不能保证模型始终正确识别每条需求的相关性。

## 验证

临时 SQLite 捕获实际本地和 A2A 请求，核对窄任务不含无关补充或被纠正的原要求，全局核对包含完整有效需求清单，展示与交付一致。覆盖 legacy 有指令及无指令分支、v2 非法指令拒绝、应用层无效指令在 pin/commit 前失败、三种工具的有界纠正、恢复指令原子回滚及 action 幂等。新格式指令与恢复事实均持久保存，重建服务复用已提交尝试。沿用 ADR 0025 多次续接与预算回归，并执行仓库全部固定门禁和架构检查。
