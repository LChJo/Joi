# 自主进化设置页

## 设计判断

这是供 Joi 使用者查看方法学习进展、理解下一步并控制花费的产品设置页。沿用现有森林绿与纸色、系统字体、12px 容器与 8px 控件圆角，采用低动效、克制的设置页语言。

## 现状审计

原页面将全局预算、本工作台参与、原始阶段、案例计数、实验结果和旧版合成资料串成同等权重的文本。用户需要自行分辨当前进展与已结束实验，预算档位没有直接显示额度，评测按钮横向铺满，旧版干跑与历史占据主流程。

截图中的 99 / 150 是今日共享调用用量；最近一次实验的 99 次调用与 137,008 tokens 是该实验的成本。两者须分别标注。4 个开发案例、0 个独立评测案例和 4 个可复现问题是案例准备情况，不能仅凭独立案例为 0 推断最近一次评测失败的原因。

## 页面结构

1. **当前进展**：用唯一的重点容器承载可理解的状态、下一步、正在进行或最近一次评测、案例准备情况和手动评测入口。开关关闭与暂停优先于原始阶段；最近评测的结果与下一步分开描述。预算消耗不作为学习进度。
2. **已采用的方法**：只展示生效或正在生产试用的方法。模块、适用范围、状态和收益直接可见；详细通过数与真实任务数收于“评测依据”。回退并暂停是次级操作。空状态解释评测通过后才采用新方法，目前继续使用现有策略。
3. **学习设置**：集中放置全局开关、共享预算、预算档位、本工作台参与和对应恢复操作。预算档位直接显示数值；今日消耗用绝对数与预算条呈现，额度为 0 时只保留绝对数。

旧版评测历史、合成链路干跑、评测器版本和旧版设置回退界面不再显示。旧服务响应仅提示更新 Joi。后台审计数据与 API 不在此次界面整理中删除。

## 交互与状态

- 保留全局开关、参与开关、预算 radio、恢复、评测、回退的可访问名称与现有 API 语义。
- 手动评测说明“空闲时开始，计入共享预算”。前台忙碌或当日候选限制不由界面额外推断为禁止手动调度。
- 暂停时在对应设置行提供显式恢复操作；改变预算不暗示恢复暂停。
- 进行中的实验与最近一次评测使用不同标题；独立案例不足采用中性解释。
- 加载采用与内容区域对应的静态骨架；错误和保存反馈就地显示，不打断设置流程。
- 方法列表不展示已拒绝或已回退的方法作为正在使用的方法。

## 视觉与响应式

页面为单列主线，最大宽度 920px。重点容器内边距 20px，区域间距 24px，标题 16px，关键状态 21px，正文 13px，辅助说明 12px。复用项目颜色变量与焦点样式，所有关键说明使用 muted 而非 faint。

预算控制和方法行仅在区域内部横向排列；标题、状态和操作均允许换行。组件包含 640px 以下的两列预算布局与较窄内边距，极窄容器的案例指标逐行呈现。应用保持现有 768px 最小宽度，本次正式验收范围为 768、960、1280px 桌面窗口，不宣称移动端适配。数字采用等宽数字，原生 radio、checkbox、progress、details 和带名称的 section 保持键盘与辅助技术可用。

## 验收重点

默认视图可回答现在是否学习、接下来为什么等待、最近一次有无采用、用了多少调用。旧版资料不在页面出现；没有实际采用的方法时不夸大为已经获得收益。中英文与窄屏均保留完整控制与说明，不产生横向溢出。

## 独立设计复核

设计师实际审阅隔离 Electron 生成的浅色、深色、英文、方法依据展开和暂停状态五类截图，确认层级、结果与成本区分、空状态、恢复入口和长文换行，无阻塞问题。验证使用模拟数据，不代表真实模型收益，也未改动运行实例。

## 工程验证

- 新增三项页面行为测试先失败，再实现三段区域、评测状态区分与旧服务升级提示；手动排队反馈另有失败到通过验证。
- 相关 renderer 测试 117 项通过；完整覆盖率运行 2503 项通过、9 项既有条件跳过，覆盖率为语句 94.40%、分支 90.38%、函数 93.22%、行 96.87%。
- 完整 Electron E2E 17 项通过，覆盖支持的三种桌面宽度、双主题、英文、方法依据、暂停与零预算；Flutter 分析无问题、102 项测试通过。
- 类型检查、ESLint、架构边界、国际化检查、生产构建与 707 文件包内容审计通过。
