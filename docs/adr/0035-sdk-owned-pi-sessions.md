# ADR 0035：Pi 原生会话托管，Joi 负责流程与结果

- 状态：Accepted；实现、本地合成回归及生产构建见验证记录，未发布。
- 日期：2026-11-17。
- 设计：[重构 spec](../pi-session-ownership-spec.md)；证据：[桌面开源项目调研](../pi-desktop-session-research.md)、[接入审计](../pi-sdk-integration-audit.md)。

## 背景

普通对话虽然使用 AgentSession，但关闭其自动压缩，并在创建后覆盖多项底层 Agent 钩子；主 Joi 的 Pi 推理也维护独立上下文压缩。用户要求 Joi 管理流程与结果、复用成熟 Pi 工作过程，而不是在单个搭档执行中实施阻断性定制。四个桌面项目的源码支持官方 Session 或薄 RPC 客户端的职责分离。

## 决定

1. 在既有基础设施 worker 中使用锁定 Pi 版本的官方会话工厂和 SessionManager。Pi 独占历史、消息转换、压缩、恢复及工具循环。所有 Pi 搭档入口和主 Joi 的 Pi 推理会话均适用。
2. Workbench 在 Agent 能力层提供提示词/背景，继续承载既有工程绑定及结果归属；Partner revision 通过公开资源、技能、工具与扩展机制装配能力。业务层不持有 SDK 对象。
3. Joi 观察事件、投影状态和接收明确取消；不直接覆盖底层 Agent 回调，不按工具次数、无文件变化或无正文注入干预，不强制自定义完成工具，不通过观察存储失败中断执行。
4. Work 所需资源和能力在 Pi 启动前准入；移除 Pi 工具级 READ/WRITE 暂停与重启。普通对话保留 CHAT-15 并发规则，原生引擎不随本 ADR 改造。
5. Pi 原生私有会话为历史权威，数据库保留业务身份、结果、投影与游标。迁移旧 canonical 事实，旧自管摘要和检查点仅保留审计用途，不再驱动新会话。
6. 以可信 SDK settled 和官方执行收尾作为结果结算前提，Joi 通过唯一事务归档结果；业务验收与 SDK 结束分离。用量采集所有 SDK 付费事实，幂等归属与对账，普通统计故障不改变任务结果。
7. 普通对话由多个执行段组成；同搭档能力不变时复用，切换时使用官方序列化交接并新建原生会话，A→B→A 为 A1→B1→A2。比例继续可编辑，映射 SDK reserveTokens；工具默认并行，仅已复现冲突的主 Joi 问题/收尾工具局部 sequential。可选 work_handoff 不构成完成协议，缓存预热保留 off。

## 替代与生效条件

PI-SESSION-01–24 替代 ADR 0033/0034 及相关 SUM 验收中的 Joi 压缩策略、ADR 0023 的 Pi 内部干预、ADR 0028 的 Pi 工具级暂停，以及 ADR 0022/0025/0031 的发送侧上下文实现约束。ADR 0006 的结果闭环、ADR 0021 的统计原则及主 Joi 的业务调度不被替代。原生 Codex/Claude 的准入与执行协议保留。

活跃 Pi 路径已改为官方会话；旧算法文件和测试仅为历史证据，不被主 Joi 或搭档运行时调用。[验证记录](../pi-session-ownership-validation.md) 区分合成行为检查、生产打包与尚未验证的真实供应商/平台能力。

## 后果与取舍

减少两套会话语义的交叉维护，并更直接复用上游升级与桌面项目经验。代价是私有会话存储迁移、结果/用量归属对账及更早的写资源准入。SDK 不保证模型语义收敛；原生会话与业务数据库跨存储的一致性由结果幂等和恢复规则保证，不在工具回调中追加同步写屏障。
