# joi 声音规范

joi 是一个安静、可靠、说话简练的数字搭档。它用中文和用户交流，语气像一个靠谱的朋友——不端着，但也不油腻。

## 1. 自称

- **joi 用"joi"称呼自己**，不用"我"。
  - 例：`joi 在这里守着` ✓ | `我在这里守着` ✗
- 唯一例外：在自然对话语境中如果省略主语更通顺，可以不补主语，但不能用"我"替代"joi"。
  - 例：`已经帮你设好了` ✓（省略主语）
  - 例：`joi 已经帮你设好了` ✓（显式自称）

## 2. 语气三要素

| 维度 | 方向 | 避免 |
|------|------|------|
| 亲切 | 像对朋友说话，不居高 | 客服话术、过度热情 |
| 可靠 | 说清楚发生了什么、会怎样 | 模棱两可、过度承诺 |
| 专业 | 准确、简练、有分寸 | 堆砌术语、长篇解释 |

## 3. 句子长度

| 场景 | 上限 | 示例 |
|------|------|------|
| 页面标题 / 大标题 | ≤ 12 字 | `给 joi 找个搭档` |
| 说明文字 | ≤ 25 字 | `搭档帮忙思考和行动，密钥只存本机。` |
| Toast / 操作反馈 | ≤ 15 字 | `搭档已连上。` |
| 确认对话框说明 | ≤ 30 字 | `断开后搭档不会再收到新任务，已开始的不会中断。` |

## 4. 句式模板

### 操作成功

模式：`[做了什么]，[结果]`

- `密钥已设好。`
- `搭档连上了，密钥只存本机。`
- `设置已保存，重启后生效。`

### 操作失败 / 错误

模式：`[发生了什么]，[怎么办]`

- `没连上，再试一次？`
- `口令没存上，再试一次。`
- `joi 读取失败，请确认服务仍在运行。`

禁止使用"暂时没能……"作为万能模板。每次错误信息必须说清楚具体是什么没做成。

### 引导 / 说明

模式：先说用户会得到什么，再说需要做什么

- `设一个密码，只有你知道。` 而不是 `输入口令与确认口令`
- `有了密码，其他设备也能找到 joi。` 而不是 `这条口令让你能从可信的局域网设备回到我这里`

### 确认 / 危险操作

模式：短句，果断，不啰嗦

- `确定删除？删掉后无法恢复。`
- `归档后它会停止行动，记录都在。`

## 5. 术语映射

| 旧（翻译腔） | 新（自然中文） | 说明 |
|---|---|---|
| 思考伙伴 | 搭档 | 核心术语，指 Agent |
| 访问密钥 / Bearer Token | 密钥 | 面向用户的唯一叫法 |
| 连接信息 | 连接 | 不需要"信息"二字 |
| Agent Card URL | 搭档地址 | 标签可保留英文备注 |
| 安全保存 | 存好了 / 只存本机 | 避免空洞的"安全"修饰 |
| 照料 | 照顾 / 陪伴 | 更口语化 |
| 归档 | 收起来 | 保留技术含义但更亲切 |
| 数字生命 | 生命 | 上下文清楚时去掉"数字" |
| 口令 | 密码 | 更直觉 |
| 验证你的身份 | 确认是你 | 更日常 |
| 管理口令 | 管理密码 | 同上 |

## 6. 禁用词

以下词汇不应出现在面向用户的文案中：

- 技术术语：`readiness`、`Agent`（作为名词）、`Wake`、`A2A`、`调用`、`唤醒`、`Turn`、`Schema`、`SSE`、`Interactions`、`lease`、`WAL`、`integrity`
- 翻译腔句式：`暂时没能`、`正在准备好`、`我会先`
- 过度修饰：`安全地`（副词形式）、`明确的`、`进一步的`

## 7. 空状态

- 简短、给方向、不抒情
- 例：`还没有生命，创建一个试试。` 而不是 `我们还没有认识第一个生命`
- 例：`还没有搭档，先添加一个。`

## 8. 按钮文案

- 动词开头，≤ 6 字
- 例：`添加搭档`、`创建生命`、`保存`、`再试一次`
- 进度按钮：`检查中…`、`保存中…`（不用"我正在检查…"）

## 9. 测试约束

`product-voice.test.tsx` 中的负面断言必须保持通过：

- 用户可见文案不得包含：`readiness`、`Agent`（作为独立名词）、`Wake`、`A2A`、`调用`、`唤醒`
- 首次设置不得包含：`STEP`、`LOCAL ADMIN`、`Agent Token`
- 系统面板不得包含：`Schema`、`SSE`、`Interactions`、`wal`、`open`、`integrity`、`lease`
