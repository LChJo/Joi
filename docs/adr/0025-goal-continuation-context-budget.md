# ADR 0025：目标继续的结论背景与累计预算

- 状态：accepted
- 日期：2026-10-10
- 关联：ADR 0010、0017、0022；AC-14/AC-33/AC-46/AC-53/AC-67

## 上下文累计逻辑

主 Joi 会话键包含工作台和原始 goal id。显式继续复用原输入，恢复和 Wayfinder 评审绑定同一 goal；结果综合使用独立 synthesis 会话。新提交输入使用独立 goal id，即使文字相同也不继承另一目标的历史。

`SqliteJoiInboxRepository.retry` 保存累计用户正文并重新排队。`JoiCoordinator` 将当前请求交给 Pi；Pi 每轮追加用户消息、模型消息及工具结果，随后保存会话快照。主会话与结果综合会话分离意味着综合结论不能仅靠主会话 transcript 延续；搭档已有的同目标证据传递也不能替代主 Joi 在分工前读取结论。

Pi 在轮次开始和结束检查窗口余量，默认达到窗口 85% 或超过 200 条对话消息时压缩；消息数量触发默认保留 80 条，窗口触发逐级缩小尾部。压缩摘要最多 12,000 字符，供应商摘要失败使用有界本地回退。轮内逐请求字符裁剪带遗漏标记，独立于持久压缩。用户配置的模型窗口与压缩阈值覆盖默认值。这些机制管理会话历史，不能防止单个新 prompt 重复携带整份旧结果，亦不保证模型一定沿用已有结论。

## 决策

1. 本次继续要求独立保存在 `continuation_prompt`，作为本轮用户 prompt；留空继续保存明确的续跑要求。累计正文保留用于本地展示和追溯，不整份重发。手动继续清除旧定时来源，定时继续仍使用其当前 Routine prompt。
2. 主编排在继续、恢复和评审时读取同目标、同工作台的结论、决策及已完成 Work 证据。权威过滤与搭档执行共用：只接受最新派发、非迟到、权威且未验收失败的完成结果。背景以旧结论为分析起点；要求变化或新证据冲突可以重新核验，禁止把旧完成 disposition 当作新请求已经完成。
3. 背景采用每请求替换机制。`StartReasoningTurnInput.backgroundContext` 是 24K 默认背景，`backgroundContextVariants` 携带 40K、60K 两档更完整的候选，内容相同的候选去重。每次 provider 请求只选择一份合入当前系统提示词，候选均不进入用户消息、会话快照或压缩摘要。轮次修复仍获得当前背景；会话重建和模型源切换重新加载持久事实。相同证据多次继续只保留一份请求背景，不在线性增长的 transcript 中留副本。
4. 应用层背景软目标 24,000 字符，可选 40,000 和 60,000 字符，上限 60,000；各档预留 2,000 字符给指令，其余结构化数据按 JSON 编码后长度衡量。原始请求及累计回答有界保留首尾，结论优先保留，决策至多 8 条、雾区至多 6 条、结果至多 24 条。单结果正文限额随档位分别为 6,000、10,000、15,000 字符。超长正文保留首尾、截断标记和 resultId；产物只带有界元数据及真实数量。超额时收缩正文，必要时移除较早结果并记录省略数量。完整正文仍在私有结果存储，可通过 `work_read_result` 按需读。
5. Pi 每请求按当前模型窗口、固定系统提示词、当前消息（含本轮 prompt/图片）、当前工具 schema 和输出余量计算可用容量，从候选中选择可容纳且通过 SDK Token 余量检查的最完整一档。字符容量不超过模型背景份额扣除固定提示词，同时不超过整个请求的剩余容量；工具 schema 从 transcript 的声明与当前工具集合中只计一次。请求字符预算和配置的压缩阈值均预留输出空间。未知或无效窗口不自动扩展，沿用 24K 软目标。空间不足时可缩至 24K 以下并附截断说明，固定权限提示词和当前用户请求保留。

## 影响与边界

累计用户正文与实际对话依然会增长，它们代表真实输入及执行事实；既有 Pi 压缩负责真实对话增长。本改动消除重复历史正文和证据副本造成的增长，并给单次背景一个有界、自适应的上限，不承诺 Token 消耗恒定。模型窗口较小、结果很多或报告极长时，模型仍需按引用读取截断部分；结论可能随新证据修正。增加候选不要求先裁掉历史来腾空间，剩余容量不足时优先回落背景档位；整段会话超过既有压缩门槛仍正常压缩。

不回写运行中任务，不重放历史 Work，不改变恢复门禁、outbox、派发幂等或新输入隔离。背景正文不进入首页、DTO、safe snapshot、诊断或 SSE。

## 验证

临时 SQLite 测试捕获继续、回答恢复及评审的编排输入，核对根因位于短摘要之外仍可见、最新补充独立发送、旧结果过滤、新目标隔离及扩展候选送达实际 runtime。Pi 假供应商测试连续 12 次继续并多次重建 runtime，验证每次请求只包含当前证据一份、持久快照不含背景；200k 窗口下分别验证空会话选 60K、较大固定提示词选 40K、长历史/长本轮输入/大工具 schema 回落 24K，以及未知窗口默认 24K。预算测试覆盖三档正文覆盖量、多结果、多决策、大产物清单、中文及 JSON 转义放大；完整固定门禁按仓库要求运行。
