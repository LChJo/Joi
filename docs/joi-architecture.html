joi · 数字生命 Runtime Hub 架构

Electron 桌面常驻 · 六边形分层 · actor 树单根 tick 事件驱动内核 · 唯一 joi + Pi 推理基座 + 工作台编排（ADR 0001–0010）

设计原理

  • • 唯一调度权威：全局单一 joi + Pi 唯一主推理基座，工作台只是上下文聚类，绝不成为第二个调度器（ADR 0002）
  • • 六边形分层：domain 纯 TS、ports 依赖反转，CI import 边界脚本强制执行允许矩阵，违规即失败
  • • 先持久化再行动：所有外部副作用走 transactional outbox + 稳定幂等标识，崩溃可重投
  • • 以遍历代替通知：actor 树 2s 单根 tick 收敛，回调/SSE 只观测不承载控制流（ADR 0009）

可靠性与安全

  • • 崩溃恢复：启动首 tick 孤儿扫描（UNKNOWN 终态 / RESIDENT 续跑 / A2A recover），lease + 心跳校验
  • • 凭据隔离：safeStorage 加密、Bearer 只在主进程解密发送，永不下发 renderer 与日志
  • • 网络 fail-closed：loopback 常开保桌面可用，LAN 绑定失败不影响；出站 DNS 策略 + breaker 冷却
  • • 结构化澄清：user_ask 持久可恢复；连续即时失败写独立失败态停摆，绝不伪装成用户取消

工程事实基线

  • • ~26.2k 行 TypeScript · 196 个源文件 · 10 份 ADR（0001–0010）
  • • SQLite WAL + FTS5，40 次显式迁移；展示面与运行事实分离（migration 033+）
  • • /api/v1 约 34 个资源族，写请求 Idempotency-Key，错误统一 code/requestId
  • • 155 个测试文件：unit / integration / contract / renderer / e2e 五层 + 架构边界测试
