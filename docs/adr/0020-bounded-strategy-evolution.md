# ADR 0020：工作台范围内的受限策略进化

- 状态：Accepted
- 日期：2026-09-22
- 关联：ADR 0002、0010；AC-EVO-01 至 AC-EVO-06

## 决策

第一阶段自动演化上下文组织与完成证据检查。Domain 限制策略为预置操作的声明式组合，一批仅改变一个模块；不修改代码、人格、权限、验收器或清图事务。策略绑定原工作台与目标，新目标采用当前版本，旧目标固定版本。

基于稳定 Goal/Work/verification 事实记录经验，不将模型自称完成作为客观成功。上一批次得出裁决后，至少十个新观察的可评价任务、其中三个独立任务验收失败才再次启动开发评测；已裁决批次不再消费其触发证据，基础设施原因结束的批次保留触发以便重试。提案必须指明至少三个开发场景的失败及预期改善，并经复测证实。原始私有内容不进入公开 DTO 或诊断。开发与封存场景独立；评测调用使用真实推理与模拟工具，不能重复生产副作用。

后台扫描只投递持久任务，执行复用 Joi 单槽位，用户输入优先。模型调用先写出站记录并预留独立日额度；出站记录仅供审计，不进入通用出站调度器。额度以关/低/中/高（0/50/150/400 次每日）预设管理，默认低档，关档只记录经验。每次调度只执行一次有界调用，额度不足次日继续。瞬时调用失败与崩溃恢复语义一致：保留批次与已完成试验，仅丢弃被中断的尝试，当日停车、次日继续；连续三次失败才放弃批次。调用中断按稳定标识保留审计，未知调用消耗不退款。每天最多一个候选。

晋升要求三十个不同封存场景、基线与候选各三次，硬违规为零，各场景成功次数不降，总成功率增加至少五个百分点，平均模型调用增幅不超过百分之十。模型/工具/评测版本不匹配时拒绝发布。前十个可评价生产目标出现固定验收失败或明确负向反馈（入口在目标卡片）时回退，冻结该候选。硬违规、成本超限与生产回退冻结该策略于当前模型版本；其余拒绝允许同一策略再提案一次，之后冻结。封存场景集在每次评测器版本升级时轮换，缓解小样本与自适应复用带来的判定噪声。

首版使用十个固定开发场景与三十个固定封存场景。生产经验提供触发条件与版本效果监控，模型从模拟轨迹诊断通用编排缺陷；尚不从生产对话自动生成新评测题。一次完整批次包含开发、候选复测、封存对照共 240 次模拟运行与一次提案，每次模拟最多六次调用，因此最多预留 1441 次调用（不含崩溃恢复重试），可跨多个 UTC 日推进。预算是调用次数上限，不是费用金额。自动化测试使用替身，只证明流程和门禁，真实模型收益需启用后验证。

## 验收映射

- AC-EVO-01：严格策略解析、单模块修改、固定强约束；Domain 单元测试。
- AC-EVO-02：经验分型、工作台隔离、版本绑定、零历史重跑；SQLite 集成测试。
- AC-EVO-03：单槽位、预算预留、幂等恢复、用户任务优先；应用与存储测试。
- AC-EVO-04：独立评测、对照轨迹、量化晋升、组合回归、回退；评测与策略测试。
- AC-EVO-05：设置/状态/历史/回滚 API 与工作台详情页签前端，安全 DTO；HTTP 与 renderer 测试。
- AC-EVO-06：移除自主修改人格工具，保留用户管理入口；工具回归测试。
