# Normal conversations (CHAT-01–26)

The approved prototype defines the layout; these criteria define production behavior.

| ID | Acceptance |
| --- | --- |
| CHAT-01 | Global navigation orders Joi, 对话, 工作台. Approved Phosphor icons are Heartbeat for Joi, ChatsCircle for conversations and SquaresFour for workbenches. History is grouped by workbench, searchable and retained after restart. |
| CHAT-02 | New conversation opens a blank composer. Draft workbench selection remains editable until the first accepted message; the server rejects changes afterwards. Path-only quick creation derives a workbench name and binds a validated directory. |
| CHAT-03 | Independent network, partner, Skills and attachment selectors open directly. Networks come from Settings and have no model override. Settings is reachable through a button and Ctrl/Command+,. |
| CHAT-04 | Each message snapshots configuration, is submitted idempotently, and produces a formatted progressive stream. Stop preserves partial output. History, failures and interrupted execution remain readable without replaying tools. |
| CHAT-45 | Committed safe turn snapshots reach the selected conversation over authenticated SSE while the model is generating, including short answers. A throttled final prefix flushes within 100 ms even when the model pauses. Streaming sends only the current turn and safe context, preserves loaded history, drafts and edited titles, and ignores older in-flight refreshes. Disconnect or unavailable SSE falls back to 100 ms cursor-based refresh; the connected stream retains a 700 ms recovery refresh for durable metadata and child updates. Completion/stop closes the stream, and switching conversations or unmounting releases it. Transport backpressure retains only the newest pending snapshot and heartbeat checks end revoked sessions. |
| CHAT-05 | Turns use existing source readiness, partner policy, Skill validation and checkpointed tool permission phases. Concurrent requests cannot start two active turns in one conversation. Normal conversations do not acquire the autonomous workload's workspace leases (CHAT-15). |
| CHAT-06 | Each turn inherits its immutable workbench's available memory and validated effective evolution. Empty, disabled or incompatible states are truthful. Conversation bodies do not become learning evidence automatically. |
| CHAT-07 | Right workspace separates attributed artifacts from whole-repository status. Git supports single/all stage and unstage, staged-only commit, local branch select/create, fetch, fast-forward-only pull, push and bounded history. Mutations are durable, idempotent and share workspace exclusion; interrupted mutations are not replayed. |
| CHAT-08 | Diffs support unified and side-by-side views. Workspace file browsing rejects traversal/symlink escape. Browser preview accepts only explicit HTTP(S) navigation in a sandbox. |
| CHAT-09 | Authenticated HTTP reads and CSRF/origin-protected writes preserve desktop-only local filesystem access. No credentials, private thinking or raw tool bodies enter diagnostics or stream projections. |
| CHAT-10 | Desktop/LAN renderer uses shared DTOs and /api/v1 only, supports narrow layouts, keyboard submission, independent drafts and safe Markdown. No task decomposition is shown in the main conversation UI. |
| CHAT-11 | Workbench selection and inheritance strip appears only before the first accepted message, returns for a new draft, and stays hidden for restored/history conversations. Workbench ownership remains in the header. Global navigation can be collapsed to icons and expanded with an accessible lower-left control without resetting the current page or draft. Composer send/stop controls have distinct ready, disabled and running states, visible focus and readable light/dark contrast. |
| CHAT-12 | New drafts show neither workspace nor its toggle. Switching to a new draft resets the workspace to closed; after sending, existing conversations expose the manual toggle. Opening it exposes a draggable boundary with the conversation; its width survives closing/reopening within the page, stays within viewport/chat limits, and supports keyboard resizing. Narrow layouts keep the workspace as a bounded overlay. |
| CHAT-13 | History removes the subtitle and uses compact single-line titles. Hover and keyboard focus reveal the full title, workbench and update time without clipping. Row actions archive or delete an idle conversation; queued/running turns block both operations atomically. |
| CHAT-14 | Archive adds Tasks and Conversations tabs. Archived conversations remain readable, searchable, restorable and deletable after confirmation. Restore preserves turns/configuration and starts no execution. Deleted conversations disappear from reads/lists and cannot be restored or reused; durable tombstones preserve request identities. Archive/restore/delete are idempotent local transactions, leave workspace files untouched and never enqueue execution. |
| CHAT-44 | History row actions allow renaming a conversation, including during generation. A focused title editor supports Save/Enter, Cancel/Escape, rejects blank or over-80-character titles, and preserves edits for retry after a failed save. Successful saves update the row and selected header, remain searchable and survive restart and subsequent turns. Title-only writes are authenticated, CSRF/origin protected and idempotent local transactions; they preserve turns, configuration and execution state, enqueue no execution, and reject missing/deleted identities. |
| CHAT-15 | Conversation execution and autonomous Joi tasks do not block each other through workbench or physical-directory occupancy. A conversation starts and resumes a durable write checkpoint while another task holds READ/WRITE admission; it does not block Joi admission itself. Source/partner/tool policy, immutable workspace ownership, same-conversation turn exclusion, cancellation, idempotency and interrupted-execution protection remain authoritative. Graceful close preserves queued turns; startup clears legacy admission backoff only for pending, never-started conversation turns. Explicit emergency stop cancels queued turns. Explicit Git mutations retain repository coordination. |
| CHAT-16 | Consecutive tool entries form a compact disclosure, collapsed by default. Its summary shows the latest tool and total calls; matching call/result entries count once. Expansion shows ordered calls. Streaming updates the summary without closing an expanded group. Prose, errors and artifacts retain their chronological positions; narrow layouts and keyboard disclosure remain usable. |
| CHAT-17 | Both the latest-tool summary and expanded calls show the tool's safe parameter summary and execution state. Commands, paths and queries use the existing bounded, secret-masked projection; raw results and reasoning remain private. Explicit tool failure survives normalization and conversation persistence; legacy failed-result markers remain readable. Unfinished calls distinguish running, stopped, interrupted and unrecorded results; missing parameters are identified rather than invented. Long summaries truncate within the collapsed row and wrap when expanded without page overflow. This presentation change does not impose execution limits. |

Production completion requires focused behavioral tests plus the fixed repository gates in `.agent/commands/README.md`. Actual provider calls and remote Git writes are not part of automated verification; disposable engines and local repositories are used.

## Continuous context acceptance

| ID | Acceptance |
| --- | --- |
| CHAT-18 | Codex and Claude receive complete mandatory context in actual SDK inputs, including persona, current requirements and attachment references. Native SDKs retain their own session management. |
| CHAT-19 | Each conversation owns a durable private execution session, isolated from other conversations and disposable partner instances. Complete available history and checkpoints survive restart, stop and failure; unknown effects are never replayed automatically. Legacy imports retain an internal missing-private-history marker; CHAT-37 omits its explanatory text from the UI. No recent-24-turn concatenation or string slicing is used. Model/partner changes inherit available history. |
| CHAT-20 | Shared Joi compaction accepts only complete text responses with net savings in the serialized outgoing view, preserving original history and the previous checkpoint. Session/source-revision failures back off 30/120/300 seconds across changed candidates, restore and READ/WRITE phases; cancellation neither increments nor clears failure protection. Soft pressure runs one bounded background summary; hard capacity waits at most five seconds before explicit safe fallback or capacity failure. Frozen coverage and execution epochs reject stale results. Final prompts, checkpoints, notices and tools are sized together; protected context is never silently clipped. Generation allowance follows model capacity, independently of the summary character target. Diagnostics contain only safe reasons and numbers. SUM-01–12 and ADR 0034 refine this criterion. |
| CHAT-21 | Pi 1.5.2 and pi-subagents 0.88.0 are locked and bundled for offline loading. Conversation Pi SDK sessions use Joi's context policy with SDK automatic compaction disabled; primary Joi retains goal/Work scheduling and rollback. |
| CHAT-22 | Enabled-by-default, switchable Pi subagents inherit the parent's pinned model, workspace, selected tools and permission ceiling. Stable child identities and outbox intents precede execution. Query, cancel and interrupted outcomes are durable. Parent settlement waits for children and cancellation reaches them. No unknown child execution is automatically replayed. |
| CHAT-23 | Desktop shows safe context character estimates, compression state, recent activity and child progress. These are estimates, not billed tokens or claims about answer quality. |
| CHAT-24 | Authenticated /api/v1 history pagination and event cursors recover updates after reconnect without exposing raw session state or cross-conversation history. |
| CHAT-25 | Chinese long histories, expanding/failed summaries, large tool results and protected overflow have regressions. Original compressed history remains pageable and complete tool call/result exchanges remain paired. |
| CHAT-26 | Synthetic prototype comparisons become regression evidence for summary calls, serialized characters and recovery. They make no claim about long-term memory quality or token savings. Branch editing, queued follow-ups, import/export and extension marketplace remain later work. |
