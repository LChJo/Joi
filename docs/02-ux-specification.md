# 交互与页面规格

2026-10-20 主页采用用户选定的 C2 紧凑阅读方案（`design/joi-home-c-compact.html`）。任务有独立底色、8px 间距和 12px 纵向内边距，页面标题 26px、目标 15px、元信息 12px；结果摘要降为两行正文并常显全文入口。圆形徽章使用现有 Phosphor 工作台图标，分类缺失时不从任务名称猜测类型。输入器最大 680px，空闲时收为命令条；聚焦、草稿、附件或显式分发选择时展开，保留 16px 底部安全距离。正文列表独立滚动，最后一项和二级菜单都必须可见可点。输入法组合期间不响应提交快捷键，普通 Enter 换行，Ctrl/Command+Enter 提交。首页不增加任务流分区标题。

## 0. JOI-01 首页与首次连接

目标详情的标题保持紧凑；悬停、聚焦或点击可阅读完整安全目标文本，右键或键盘菜单提供“复制全文”，复制结果须有成功/失败反馈。全文对应首条用户目标，经过既有敏感信息遮蔽和路径缩写；不能把首页 120 字符摘要当作全文。正文提示框支持滚动与手动选取，Escape 先关闭提示框或菜单，再退出详情。

标题全文提示以鼠标位置偏移显示，在标题内随鼠标移动，进入正文框后固定以便滚动选取；点击可固定全文供触屏阅读。右键菜单固定在触发坐标，键盘操作锚定标题底边；两者均避让视口边缘，外部滚动、缩放、点击可关闭，框内滚动保留。复制失败保留可选全文。

目标路线图默认显示紧凑概览：两行目的地、全量路径/决策/雾区总数、当前层与展开入口。展开后在有界滚动区域按路径、决策、雾区分区查看；最新层优先且默认展开，历史层可展开回看，同层路径并列，窄屏堆叠。路径与 Work 状态分别展示；连线表示层级推进，不推测依赖。点击路径就近查看完整说明及决策、雾区晋升关系。总数与已加载数明确区分，历史记录通过详情内“加载更多”读取。同名路径按稳定 ID 保留。收起重开和 HTTP 轮询保留分区、选择、展开层、已加载页及内部滚动位置，失败保留最后成功内容并提供重试。首页继续使用摘要投影，地图没有编排写入能力。设计师评审及线框见 [目标详情 UX 评审](design/goal-detail-ux-review.md)。

主导航侧栏在 joi、工作台、搭档、定时任务、设置、统计和已归档之间切换时保持同一套字体、字号（14px）、图标间距、圆角、背景和分隔线。选中态通过文字颜色、字重和背景高亮表达；页签切换不得改变侧栏或导航项的位置及尺寸。亮暗主题和窄窗口的折叠侧栏均遵循此标准，页面加载中也不改变侧栏样式。

首页是单栏、可持续清理的信息流，不设右侧工作状态面板。joi 尚在处理的 Turn 保留字面量 `progressing`，并在同一行补充安全的阶段、Agent 数、Work 完成计数和已用时间；阶段只使用 `正在整理任务`、`正在拆分工作`、`正在安排搭档`、`搭档执行中`、`等待搭档回应`、`正在汇总结果`、`正在评审结果`、`评审后补充执行` 等枚举文案，不显示 ETA、原始执行消息、模型标识、路径或错误正文。Turn 结束后只以较小字号短暂停留 15 秒，然后自动消失。具体执行不再拆成“工作进展 / 工作已安排 / 搭档结果”过程行，而是按用户最初目标聚合为工作台卡片：同一工作台的两个目标仍是两张卡；卡片显示工作台、目标、Agent 数、Work 汇总和安全结果摘要，点击进入对应工作台。每一层 result outcome 只是 Wayfinder 的待评审总结；ACTIVE map 必须继续显示 `正在评审` 或 `评审后补充执行`，只有复盘 turn 提交 `MAP_CLEARED` 后才展示最终回答、标记“已完成”并开放继续/删除。若综合明确请求安全的下一证据层，Joi 默认自动续跑两层；额度耗尽后原目标卡就地显示“继续完善/保留当前结果”，接受后标记“已完成（有缺口）”并保留缺口摘要。Joi 已确认现有已验收结果足够回答原目标时，单个失败 Work 不得覆盖目标的“已完成”终态；最终回答保持主体，失败只显示为弱化的“搭档异常”入口，点击直接打开失败 Agent 的脱敏错误流。无 Work 的直接回答也必须在 Turn 完成事务中形成有界脱敏的持久结果，刷新或重启后继续在原目标卡显示，不能依赖私有 reasoning transcript。只有所有 Work/Run 都终态且 Wayfinder 已收官的目标卡可以删除，删除后不因轮询或重启复活。卡片不再平铺操作链接：每张卡的右上角是一个 `⋯` 图标按钮，展开的二级菜单按状态给出 `继续`、`取消任务`、`归档`、`移除`，卡片干净时只剩一个可点的入口。`归档` 是 `移除` 的可逆对应物——只有终态且没有仍在执行的 Work/Run 的目标可以归档，归档后卡片离开首页信息流、进入侧边栏的「已归档」，在那里可以取消归档放回首页、继续、或同样地移除；因此归档比移除早一步可用，未定稿的失败卡也能收纳。「已归档」页的卡片是紧凑形态——只留工作台、目标与归档时间，进度、Work 计数与结果正文收进点开的详情，因为这是一份收纳清单而不是第二个信息流。归档不销毁任何东西，也不停用定时续跑：一旦目标被重新激活（显式继续或定时任务到点），归档标记在同一次写入里清掉，重新跑起来的目标不会继续隐身。终态目标点击“继续”后，在 HTTP 接口确认持久化之前立即显示本地 `正在提交继续请求`，确认后无缝切换为 `queued`/`正在安排`；服务端同时重新激活既有 Wayfinder map、保留历史和评审水位，使补充要求重新经过 Work、综合与评审，不能沿用旧的 `CLEARED` 终态直接完成。提交失败则撤销该临时阶段、显示具体安全错误并保留重试入口，不能出现无外显变化的空白窗口。需要澄清的输入仍在流里就地可操作：归属不明确时点选工作台；缺少工作目录时直接选择目录；确需用户决定搭档时显示当前可用搭档卡并点击继续；joi 提出阻塞问题时显示具体问题并就地回答。工作台、搭档、模型源与诊断是按需展开的次级界面。

不存在 `READY` 模型源时，首页主文案必须精确显示“joi需要链接到大模型网络”，并展示恰好 7 个厂商级入口：Kimi、GLM、Qwen、Doubao、MiniMax、DeepSeek、通用平台。产品界面不出现转发或聚合平台。配置采用“厂商 → 接入方案 → 接口协议”结构：先选择普通 API 或官方 Coding Plan / Token Plan；该方案同时支持两种协议时，再选择 OpenAI-compatible 或 Anthropic-compatible，只支持一种时直接进入表单。

- Kimi、GLM、Doubao、MiniMax 分别提供普通 API 与 Coding/Token Plan 二级选项；Qwen 明确拆分百炼 API、百炼 Coding Plan、百炼 Token Plan；DeepSeek 当前仅显示 API；通用平台直接进入自定义配置。
- Kimi Code、GLM Coding Plan、Qwen API/Coding Plan/Token Plan、Doubao Coding Plan、MiniMax API/Token Plan 提供 OpenAI-compatible 与 Anthropic-compatible；Kimi API、GLM API、Doubao API、DeepSeek API 仅提供 OpenAI-compatible。
- 官方接入方案仅显示对应 API Key、推荐模型与高级 Model ID；endpoint 由接入方案和协议共同固定且不展示、不编辑，普通 API Key 与套餐 Key 不得混用。
- 百炼 Token Plan 的 OpenAI-compatible endpoint 固定为 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，Anthropic-compatible endpoint 固定为 `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic`；它与百炼 Coding Plan、百炼按量 API 的 Key/Base URL 完全隔离，不得混用。
- 已验证为 `READY` 的 API、Coding Plan 与 Token Plan 来源都可成为全局 joi 的主源或备用源；套餐表单明确提示订阅权益通常面向个人交互式使用，用户需遵守厂商条款。
- 通用平台先选择 OpenAI-compatible（走 OpenAI Responses 接口）或 Anthropic-compatible Messages，再填写显示名称、Base URL、API Key、Model ID；localhost/127.0.0.1 可留空 Key。
- 验证失败时保留草稿、设置和诊断入口，但普通 composer 继续门禁；界面按鉴权、模型不可用、接口不可达给出可操作提示；验证旁提示兜底最小文本请求可能产生极少量费用。
- 普通首页只保留正在推进的 `progressing`、需要用户处理的澄清/确认，以及按原始目标聚合的工作台卡；连续输入无需用户选择串行或并发。

### 0.1 搭档页与搭档配置

搭档页是 joi 的统一搭档目录，顶部用“场景预设 / 搭档目录”两个页签切换；搭档目录以卡片网格展示全局能力模板。搭档少于 2 个时，首页与搭档页都提醒用户用场景预设或手动建立团队。首页输入区为融合的聊天气泡（文本框 + 底部工具行：左侧附件和分发选择、右侧“交给 joi”），随视口锚定在窗口底部并保留约 16px 安全间距。澄清卡按原因码分为工作台归属、工作目录、搭档选择和问题回答四种操作形态；搭档选择只列出 ACTIVE 且配置有效的搭档，以稳定 ID 提交并隐藏自由输入，接口和页面均不暴露绝对路径或实例内部信息。

工作台详情默认展示它启动过且尚未被用户删除的全部 Agent，包括本机 Pi、Claude Code、Codex 与远端 A2A。每张 Agent 卡显示搭档名、transport、engine、会话策略、最新状态和时间；这里的 `IDLE/BUSY` 表示 resident instance 的全局可用性。沿某条目标进入 Agent 列表时，状态必须改由该 Agent 在该 goal 中的活跃或最新 partner run 投影，已完成 run 显示 `COMPLETED`，不得被已回收可复用的 instance `IDLE` 覆盖。一次性 `EPHEMERAL` Agent 只有终态才出现删除按钮；`RESIDENT` Agent 永不可从这里删除。删除只清理 Agent 展示卡和展示对话，不删除 Work、Result 或审计事实。原工作台人格、职责、工作区和安全结果元数据移到“上下文设置”次级页签。

点击 Agent 进入最终一级的只读对话流。对话支持 Markdown/GFM、工具调用、工具结果、产物与错误块，不提供直接输入框；用户可返回后从主页继续给 joi 输入。本机 pi-core Agent 运行时必须先显示任务，再以短间隔持续更新可见回答；工具过程只显示工具名和执行完成/失败，不显示参数或原始结果。运行终态以完整脱敏投影原位替换临时流，不重复任务、工具或回答。选中 RUNNING/WAITING Agent 时界面每 750 ms 刷新，终态停止刷新，较旧的 HTTP 响应不得覆盖较新的快照。原始引擎消息、内部推理和 A2A data payload 不进入该投影；路径、Bearer 与命名密钥在持久化前脱敏，远程图片不加载，链接只允许显式 HTTP(S) 新窗口导航。只要用户没有删除一次性 Agent，对话可跨重启回来查看。

工具调用和工具结果在 Agent 工作记录中默认降级为单行摘要，只显示“调用工具/工具结果”、工具名和时间；存在安全正文时可由用户展开，默认不占用正文卡片高度。Agent 终态产物与目标最终结论汇总的产物使用同一文件卡：桌面窗口点击直接交给系统打开，右键在系统文件管理器定位；目录产物点击直接打开目录。局域网浏览器不显示可操作按钮，也不能调用桌面打开接口。产物卡只接收稳定 ID、名称、MIME、大小和文件/目录类型，绝对路径与内部相对引用均不进入 renderer DTO；主进程在每次动作时从权威工作台绑定重新解析并验证 realpath，越界、缺失或符号链接逃逸一律拒绝。

添加搭档先选择模式：本地搭档（本机引擎执行）或远端 A2A（通过 Agent Card URL 与 Bearer Token 登记，能力以 Card 为准合并）。本地搭档编辑分为基础与高级两页：

- 基础页：两列对齐布局——名称、描述（给 joi 派发做参考）与搭档提示词；知识库附加 md 文档（不超过 8 篇、每篇不超过 256 KiB，内容导入本机数据库并随备份恢复）；技能按当前引擎扫描本机已安装技能（`~/.claude/skills` 等）以点选复选框呈现，无手填、无"能力标签"。已有提示词默认隐藏，页面只显示是否已配置；用户必须点击“查看提示词”触发受写权限保护的显式读取。查看后可选择完整替换，或仅提交追加内容由服务端用空行连接到当前提示词。
- 高级页：搭档引擎三选——Pi core（默认）、Claude Code、Codex；后两者只探测用户环境安装的 CLI，未检测到时明确提示并由服务端拒绝保存。Pi core 显示模型源、模型与工具白名单；Claude Code 显示模型覆盖和工具白名单，并明确要求 Joi 进程环境提供 `ANTHROPIC_API_KEY`。Codex 显示模型覆盖与官方权限控件：工作区只读/可写、网络开关、网页搜索 disabled/cached/live；approval 固定 never，界面不提供 danger-full-access，也不再伪装成工具白名单。详见 ADR 0014。
- 每张本机搭档卡都提供显式测试动作。Pi core 测试受管模型；Claude Code 与 Codex 必须通过各自官方适配器启动无工具最小调用，不能只以 PATH 存在冒充可用。Claude 缺少环境 API Key 时显示明确配置提示；其余失败按认证、模型、限流、服务、进程或通用原因安全归类，不展示原始输出。Codex 嵌套启动继续隔离四个上层环境覆盖并只解析用户 PATH 安装；普通终端配置保持原生继承。

所有修改登记为新的不可变 revision，在途工作按旧 revision 完成（DRAIN）；复制搭档基于活跃 revision 产生独立副本，提示词与知识库另行复制。提示词正文、知识库正文与工作路径仅本机保存，不在列表接口返回；普通 Partner DTO 只可返回 `promptConfigured`，提示词正文仅由显式 reveal 响应返回且禁止缓存。替换和追加都生成新的私有提示词引用与 Partner revision；知识库只注入本机引擎的系统提示词，不发给远端 A2A。

下文“全部生命/生命创建向导”描述迁移前界面，只用于旧版本回归；JOI-01 上线后由本节替代。

### 0.2 场景预设

场景预设位于搭档页的“场景预设”页签（不在首页铺陈，避免首屏过载），主目录统一使用可展开的套件形态，不再显示平铺单场景卡。`编程套件`包含功能实现、代码审查、Bug 诊断和架构改进四个子团队；`调研分析套件`包含目标规划和研究综述两个子团队；`AI Berkshire 价值研究套件`保留六个专业子团队；`内置 Skills 套件`动态收纳 Pi core 当前可用且最近修改的 6 个本机 Skill，每个 Skill 是一个可单独安装的子团队。旧 `/api/v1/scenarios` 及按角色创建接口保留兼容，但不再作为主目录信息架构。详见 ADR 0005。

## 1. 体验目标

用户看到的不是“配置一个复杂工作流”，而是“认识、照料并观察一个持续存在的数字生命”。默认路径必须短：连接 Agent、描述它是谁、点击出生。事件、协议、context 和恢复细节只在需要诊断时出现。

## 2. 信息架构

桌面窗口与局域网浏览器共用以下导航：

```text
joi
├── 生命
│   ├── 全部生命
│   └── 生命详情
│       ├── 活动
│       ├── 事务与待办
│       ├── 记忆
│       ├── 作息与闹钟
│       └── 设置
├── Agents
├── 系统活动
└── 设置
    ├── 局域网访问
    ├── 管理员与会话
    ├── 预算默认值
    ├── 备份与恢复
    └── 诊断
```

默认首页是“全部生命”，而不是系统设置或 Agent 列表。

## 3. 首次设置

### 3.1 步骤一：管理员口令

- 只允许在桌面本机完成首次设置。
- 输入口令与确认口令；不增加用户名、安全问题或邮箱。
- 明示“该口令用于局域网浏览器访问，不会恢复加密的 Agent Token”。
- 完成后自动建立桌面本地会话。

### 3.2 步骤二：局域网访问

- 默认关闭 LAN Listener，桌面功能不受影响。
- 开启时只列出 RFC1918 IPv4；用户选择一个地址，端口默认 `43130`。
- 显示访问 URL、可信局域网 HTTP 风险和“复制地址”。
- 复选框先更新本地草稿；选择地址并确认明文风险后才允许提交。
- 保存后热切换 LAN listener，无需重启；绑定失败时保留用户的启用意图，显示明确错误并保留重试入口，桌面 loopback 始终可用。

### 3.3 步骤三：连接大模型网络

- 复用主页的大模型网络引导：选择模型厂商、接入方案与接口协议，再填写 Model ID（可选）与 API Key。
- “保存并验证”一次完成密钥保存与连通性验证；验证通过后运行时进入 READY，引导按钮变为“进入 joi”。
- 验证未通过时保留为可诊断的草稿，说明失败原因；用户可修改重试或跳过。
- API Key 保存后不再回显原文。

用户可跳过模型网络连接进入空状态，但不能启动生命。

## 4. 生命创建向导

向导只有三个步骤，并支持返回修改：

### 4.1 它是谁

- 必填：名称、人格摘要。
- 可选：头像、角色、原则、初始目标。
- 人格摘要建议 50–500 字；不要求编写 system prompt。

### 4.2 它如何行动

- 选择一个已通过 readiness 的主 Agent。
- 可选协作者，默认全不选。
- 展示主 Agent 与协作者的职责差异，不展示 Token、模型或底层 URL。

### 4.3 它如何生活

- 时区默认系统时区。
- 默认作息：08:00 计划、21:00 复盘、03:00 记忆整理。
- 默认安静时段与预算以摘要卡展示；高级编辑折叠。
- 最终按钮为“让它出生”。点击后原子创建生命与 `system.birth` 事件，并跳转活动页。

## 5. 全部生命页

### 5.1 生命卡片

每张卡只展示：

- 名称、头像、角色摘要。
- 状态：休眠、等待唤醒、运行中、暂停、等待用户、预算暂停或异常。
- 主 Agent 名称和连接健康点。
- 今日自主唤醒与 A2A 调用额度。
- 下一次已知唤醒时间、未读表达数和待处理问题数。

主操作为“打开”；启停开关只在卡片悬浮或更多菜单中出现，避免误触。

### 5.2 空状态

- 没有生命：突出“创建第一个数字生命”。
- 没有可用主 Agent：先引导连接 Agent，保留产品说明。
- Hub 暂停：显示全局横幅和“恢复运行”。

## 6. 生命活动页

### 6.1 页面布局

```text
┌─────────────────────────────────────────────────────────┐
│ 头像 名称  状态  主Agent  今日预算  下一次唤醒  [暂停]    │
├──────────────────────────────┬──────────────────────────┤
│                              │ 当前关注 / 意识残留       │
│ 活动时间线                    │ 活跃事务与待办             │
│ 用户消息 / 生命表达 /         │ 闹钟 / 等待输入             │
│ 系统事件 / Agent 调用         │ Agent 健康与调用            │
│                              │                          │
├──────────────────────────────┴──────────────────────────┤
│ 输入消息…                           [附件] [发送] [停止] │
└─────────────────────────────────────────────────────────┘
```

窄屏浏览器将右栏折叠为“状态”抽屉；时间线和输入框始终优先。

### 6.2 时间线事件样式

| 类型          | 展示原则                                                                  |
| ------------- | ------------------------------------------------------------------------- |
| 用户消息      | 中性表面、主文字色；标记“排队/已读取”；已读取只来自 Turn Injection 事实。 |
| 生命表达      | 独立头像与正文；不拼接“任务完成”等协议状态。                              |
| 系统事件      | 紧凑时间线节点，可展开查看触发原因。                                      |
| 主 Agent 运行 | 展示开始、阶段、耗时与结果摘要；默认折叠技术细节。                        |
| 协作者调用    | 展示 Agent、委派标题、状态和安全结果摘要。                                |
| input/auth    | 高亮操作卡，提供绑定原 interaction 的回答或授权入口。                     |
| Artifact      | 文件卡片显示名称、类型、大小、来源与下载/预览动作。                       |
| 错误          | 给出可理解原因、是否会自动重试、手动操作。                                |

时间线不得显示 thinking、原始 tool payload、Token、完整绝对路径或完整 A2A payload；工具摘要中的路径先缩写为「盘符/根 + 末三层」。工具调用可在折叠行显示一行 ≤200 字符的脱敏摘要，并标出正在运行的调用；完整的命令与输出只在用户显式点击展开时按本机私密正文呈现（该展开视图内绝对路径可见，这是本机调试信息，凭据仍脱敏，且 403 挡远端、不进入诊断或 A2A）。

### 6.3 输入框

- Enter 发送，Shift+Enter 换行。
- 发送后立即形成事件，不等待 Agent 接受。
- 生命运行时文案为“消息会在下一轮出现”，不提供破坏式“立即打断”；断线或重启后仍按 eventId 去重显示。
- “停止”仅在存在运行调用时出现；点击后选择“停止本次运行”或“暂停这个生命”。
- MVP 附件限制沿用 A2A 基线：最多 8 个、单个 10 MiB、总计 25 MiB。

## 7. 事务、记忆与作息

### 7.1 事务与待办

- 事务按进行中、等待、完成、失败、取消分组。
- 展示当前负责人、下一步、等待对象、关联 Wake 和协作者。
- 用户可以新增/编辑/完成待办；这些操作均写事件，不直接改 Agent context。
- 允许用户“现在提醒它”，生成高优先级 `todo.reminder`。

### 7.2 记忆

- 三个视图：意识残留、情景记忆、语义记忆。
- 展示来源时间、关联事件/事务、置信度和最后使用时间。
- 用户可以修正或遗忘一条记忆；系统保留修订审计但不再召回旧内容。
- 不显示 embedding、向量距离或数据库概念。

### 7.3 作息与闹钟

- 作息使用简单列表，不使用复杂 cron 编辑器。
- 周期选择仅提供每天、工作日、周末、每周指定日和自定义时间。
- 闹钟显示创建者、触发时间、关联事务和是否允许在安静时段运行。
- 删除或修改重复规则不会删除已经生成的历史事件。

## 8. Agents 页

每张 Agent 卡展示公开 Card 信息、连接健康、主 Agent readiness、正在被哪些生命使用和最近调用状态。

支持：

- 添加：Card URL + Bearer Token。
- 刷新 Card 与重新测试。
- 轮换 Token，不回显旧 Token。
- 停用：停止新调用，不取消已运行调用。
- 删除：必须先解除生命绑定；不声称删除远端 Agent 数据。

Card Origin、协议、transport 或认证发生变化时，卡片进入“需要重新确认”，所有新调用暂停。

### 8.1 搭档场景套件

- 搭档页的场景预设只展示套件目录；编程、调研分析、AI Berkshire 价值研究和内置 Skills 套件均可展开为子团队和共享角色。
- `AI Berkshire 价值研究套件` 展示六个子团队、十五位能力搭档、安装计数、角色状态、来源 revision 与许可证。
- `编程套件`复用原功能实现、代码审查、Bug 诊断和架构改进角色；`调研分析套件`复用原目标规划和多视角研究角色。
- `内置 Skills 套件`按目录修改时间只展示最近 6 个 Pi core 可用本机 Skill；没有可用 Skill 时保留可解释空态并禁用整套安装。
- 用户可以点击子团队的安装按钮，或点击“安装完整套件”；不要求手填角色名、提示词、Skill 路径或工作目录。
- 重复安装明确汇报新建、复用和需要处理的数量。已修改、停用、配置异常或版本落后的搭档不被静默覆盖或启用。
- 角色状态同时使用文字和颜色；需要处理时保留搭档入口与稳定原因码，不显示提示词正文、绝对路径或源仓库本地位置。

## 9. 系统设置与诊断

- 设置页使用“模型网络”“设备连接”“安全”“数据”四个顶层标签，默认打开“模型网络”，每次只展示一个分类。
- “设备连接”包含 Joi 手机和局域网访问，“安全”包含管理密码与设备会话，“数据”包含备份与恢复。
- 标签支持鼠标点击以及键盘方向键、Home、End 切换；窄屏允许标签栏横向滚动，内容保持单列且不产生页面横向滚动。

### 9.1 局域网访问

- LAN 开关、当前网卡 RFC1918 IPv4 候选、端口、当前 URL、期望配置、有效监听状态与错误。
- 不使用 `0.0.0.0`，不自动修改防火墙。

### 9.2 管理员与会话

- 修改口令会撤销所有 LAN 会话，但保留桌面本地会话。
- 按最近活动倒序展示当前会话设备，界面最多显示 10 条；允许全部退出，展示上限不改变实际会话数据。

### 9.3 备份与恢复

- 创建版本化备份、查看最近备份、选择备份恢复。
- 明示备份不包含可在其他机器解密的 Agent Token；恢复后需重新输入 Token。

### 9.4 诊断

- 展示 Runtime、数据库、事件队列、A2A Endpoint 和 Listener 状态。
- 导出默认只含状态、计数、版本和错误码，不含业务正文或地址。

### 9.5 Android 原生远程访问

- 桌面设置只配置 iroh 中继 HTTPS URL 和启用开关；默认使用 `https://remote.joilab.top`，也允许用户手动填写其他受信任的 HTTPS relay。
- “生成二维码”创建十分钟、一次有效的 `joi://pair` 绑定票据，包含应用层设备密钥和 iroh endpoint ticket；绑定成功后 App 只在系统安全存储中保存可恢复凭据。
- 已绑定设备显示名称、首次绑定时间、最近活动时间和撤销按钮。撤销后该设备不能恢复连接，重新使用必须再次扫码。
- App 只有 joi 标识、直连/中继/重连状态、首页任务卡和底部文字输入。它不提供设置、搭档管理、附件、文件、备份、诊断、删除、暂停或紧急操作。
- App 以 360–430 px 竖屏为主要视口，底部输入框尊重安全区；网络断开时保留最近一次卡片并显示重连状态，不把未确认的发送显示为已提交。

## 10. 状态与反馈

- 用户动作在 300 ms 内给出本地接受反馈。
- 长操作使用阶段状态，不使用无限旋转且无说明的 loading。
- 网络断开时保留本地可读历史；写操作明确显示“未提交”或“已进入本地队列”。
- SSE 重连后以游标补齐缺失事件，避免重复插入。
- 不使用绿色底白字作为普通用户消息或成功状态的默认样式。

## 11. 可访问性与响应式

- 键盘可完成登录、消息发送、暂停、回答 input 和导航。
- 状态不能只依赖颜色，必须包含文字或图标。
- 正文、时间线和表单满足 WCAG AA 对比度。
- Windows 桌面窗口不显示 Electron 默认的 File、Edit、View、Window 原生菜单栏；产品操作保留在应用界面与托盘菜单中。
- 支持桌面窗口最小宽度 960 px；LAN 浏览器最低适配 768 px。
- 所有日期同时提供本地时间，诊断展开区可显示 ISO 时间。
- Android App 最低适配 320 px 竖屏，并保证任务卡和输入区无需横向滚动。

## 12. UX 验收场景

1. 首次设置到生命出生不超过三个主要页面、十分钟。
2. 生命运行中发送消息，时间线立即显示排队且当前调用不被取消。
3. 闹钟触发后能从时间线追溯“谁创建、何时触发、唤醒了哪个 Wake”。
4. 两个协作者并行完成时，用户看到两个独立结果事件和后续主 Agent整合。
5. auth-required 不泄露 Token 给主 Agent，用户可在原卡片处理并恢复。
6. LAN Listener 失败时桌面窗口仍可管理生命。
7. 重启后页面恢复到真实状态，不把未知远端调用显示为失败或完成。
8. Windows 桌面窗口启动后不出现 Electron 默认原生菜单栏，托盘菜单仍可用。
9. 手机浏览器扫码一次完成绑定；刷新后可恢复连接，桌面撤销设备后刷新不能再读取任务卡或发送文字。
