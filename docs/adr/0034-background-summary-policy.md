# ADR 0034 — Background summaries with route-scoped failure protection

Status: Accepted, 2026-11-12. Refines the summary policy in ADR 0033.

Soft history pressure schedules one background summary per private execution session. The main request retains its complete available history while it fits; hard capacity may wait for that same job for at most five seconds, then uses an explicit omission projection or fails when protected context cannot fit. The existing session owner collects and validates completed results, retains work across a warm READ/WRITE suspension, and cancels and drains pending work before final execution cleanup. No global scheduler, second compaction owner or independently authenticated summary model is introduced. SDK automatic compaction remains disabled.

The retry boundary is the private session and pinned source/model revision, independently of source candidates and permission generations. Failures cool down for 30, 120 and 300 seconds, saturating at 300 seconds; accepted summaries alone clear the failure count. Cancellation neither increments nor clears it. Existing private JSON session metadata persists the protection without a schema migration. Source fingerprints, parent checkpoints and an execution epoch validate coverage and reject stale results; they do not unlock retries. Normal completion or stop can cancel unfinished work without accepting partial text.

Only a normally stopped text response without tool calls can form a checkpoint. Each accepted batch advances one frozen complete source prefix, preserves task anchors and complete tool exchanges, retains the source, and must reduce the serialized outgoing view. Regular batches target at most 64000 characters. A single indivisible exchange can exceed this soft batch target only subject to the actual summary request capacity. A campaign starts at 128000 history characters and moves incrementally toward 64000; its pending state survives accepted primary-session checkpoints.

The summary's 8000-character target is independent of its generation allowance. The latter uses the pinned model output ceiling and remaining full summary request capacity, including the previous checkpoint and SDK instructions; no fixed 8000-token cap remains. Optional reasoning is disabled; a route that requires it uses its lowest supported effort. A request-local model ceiling keeps SDK-added thinking and answer tokens inside that combined allowance without changing the configured route. Generation has an initial 60-second deadline. Oversized, truncated, empty, canceled and tool-call responses establish no coverage. Safe diagnostics distinguish generation, acceptance, bounded waiting and cleanup without content, paths or raw errors. Conversation status settles after cancellation or completion. Timing values are initial host policies, not provider service guarantees. Background work may increase temporary concurrency and full-history input cost.

The alternative of merely increasing a cap would preserve synchronous retry amplification. Enabling SDK automatic compaction would require transferring canonical history and checkpoint ownership, rather than adding a second owner. The shared policy keeps the existing primary/partner persistence and permission boundaries. [SUM-01–12](../pi-summary-optimization-plan.md) define the acceptance and validation scope.
