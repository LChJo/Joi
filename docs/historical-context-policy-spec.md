# Joi、工作台和搭档历史信息管理 Spec

日期 2026-11-19。状态为设计草案，供评审。历史预算、摘要分节、搭档经验复用和工作台原始依据读取规则已确认。其余待商榷项见第 7 节。

本地 Pi 首版实施记录见第 8 节。

## 1. 目标与可行性

Joi 只携带影响未来判断的关键全局记忆。工作台沉淀本项目的总结、用户输入摘要、经验和已生效的进化成果，并保留近期原始依据的索引。搭档积累少量可跨工作台复用的经验。三层都以分节的简短摘要保存长期信息，原始依据供运行中按需查阅。

现有架构可以承接这个设计。工作台已有目标收口后的总结回写，搭档已有结果入账和后台记忆刷新，Pi 已有原生会话和压缩。主要工作是定义三层各自的输入、读取范围与更新语义，修正旧会话迁移，并为所有模型请求补上容量检查。

| 现状 | 可复用的接点和需要补齐的能力 |
|---|---|

## 2. 三层历史和预算

历史预算是**压缩触发值**，按 Unicode 码点计数。标题、分隔符、显示的来源元数据和工作台近期依据索引计入所属层。已有历史与新条目合计达到阈值时，尝试压缩一批旧条目，再附加完整的新条目。无法可靠压缩或模型调用失败时保留原条目，允许临时超过触发值。上下文窗口和原始依据访问约束分别判定。

| 所有者 | 压缩触发值 | 保留内容 | 自动读取 |
|---|---:|---|---|
| **Joi** | **5,000** | 用户明确表示长期有效且可跨工作台使用的偏好，以及适用于多个工作台的关键编排经验。每条有来源和适用范围。 | 主编排默认读取相关的 Joi 全局记忆。按需读取的工作台摘要按工作台额度单独计量，Joi 的 5,000 仅用于自身记忆。 |
| **工作台** | **20,000** | 项目历史与结论、持续有效的用户输入摘要、已验证经验、适用的已生效进化方法，以及近期原始依据索引。五类共用额度。 | 绑定工作台的普通聊天可以继承这份投影。工作台派发只提供与当前任务直接相关的事实或少量摘要。Joi 和搭档可在授权范围内按需查询。 |
| **搭档** | **1,000** | 能跨工作台复用的处理方法、验证技巧和容易出错的边界。 | 同一 `partnerId` 在各工作台共用一份经验属性。新的 Work 按任务相关性读取，含项目细节的经验留在来源工作台。 |

### 2.1 预算的归属

- **当前任务上下文**单独计量，包括本轮用户输入、目标当前的权威需求和验收、依赖 Work 已提交的必要证据、工具和技能配置、附件引用，以及同次执行为推进任务所需的近期工具交换。可复用的经验、旧输入摘要和旧结果摘要按所属历史层计量，随请求累计去重。同一次请求读取多层历史时，各层分别计量，完整请求仍受模型窗口约束。
- **原始依据**保存在原有业务记录及引擎会话中。工作台历史携带摘要及索引，正文通过第 2.3 节按需查询。抽取新条目只使用本次合格事实，压缩旧条目独立执行。
- **同次执行的连续性**由 Pi 或对应原生引擎负责。当前 Work 的恢复、同一普通聊天的连续轮次可以沿用对应的执行身份。Joi 的新复查或续跑从当前目标的需求版本、地图状态和必要结果建立有界输入，执行会话在已结算边界切开，仍归属原目标。新的 Work 使用独立历史边界，即使复用同一个常驻搭档。明确要求延续时，通过当前任务所需的有界交接和权威状态继续，副作用可疑时使用既有恢复门禁。普通聊天可访问自己的原始会话，跨执行段的自动交接使用有界摘要与来源引用。
- **模型请求容量**另行约束。普通推理、压缩和整理历史的请求各自以当前模型可用窗口校验最终输入，计入系统段、工具定义、图片和输出预留。优先按可获得的准确计量校验，其余情况使用保守估算并保留余量。后台摘要成功与否都执行此校验。即使三个历史额度均满足，超出模型窗口的请求也应在调用提供方前得到有界降级或可识别的执行失败。

### 2.2 摘要结构

三层摘要都采用稳定章节和简短条目。写法参照 Skill 描述，先点明这条信息是什么，再写它何时适用或会影响什么决策。优先用一到两句讲清每条，合并相同信息，省略过程复述和空章节。

| 层级 | 建议章节 |
|---|---|
| Joi | 长期用户偏好、通用编排经验 |
| 工作台 | 用户输入摘要、项目历史与结论、已验证经验、生效的进化方法、近期依据索引 |
| 搭档 | 有效方法、验证要点、失败教训与适用边界 |

工作台摘要中的事实性条目引用其原始依据。例如，已验证经验可写成“变更跨平台路径逻辑时，验证正反斜杠和带空格路径”，并关联对应的验收结果。章节用于定位信息，保留篇幅由条目的有效性和相关性决定。

### 2.3 工作台近期依据索引与按需查询

- **索引。** 在工作台历史中保存近期且仍有参考价值的依据条目。每项包含资料类型、简短说明、日期或版本，以及可由系统解析的记录引用，例如某次需求修订、工作结果或验收记录。说明由系统整理，历史投影只渲染这些索引字段。索引按来源去重，优先保留较新且仍有效的记录，和其余工作台历史共用 20,000 字符额度。
- **运行中查询。** `workbench_read_history` 直接从当前授权工作台的已发布结果中按完成时间倒序列出标题、完成时间、状态和结果引用。列表含正常完成、接受有缺口结果以及历史记忆功能上线前已保存的结论。结论一经发布即可查询，后台摘要和索引按各自节奏更新。分页游标与结果引用每次都重新校验归属及有效性。可通过结果引用分页读取指定版本的结论或原始输入，也可继续解析摘要中保存的旧证据引用。现有目标证据工具继续使用自己的目标范围和门禁。 [结果读取](../src/main/infrastructure/persistence/sqlite-goal-result-history.ts) · [目标证据查询](../src/main/infrastructure/pi/joi-reasoning-tools.ts)
- **只查历史。** 用户要求只查历史时，仅使用已保存的记录。找不到所需结论时明确说明，引用较旧结果时注明其完成日期。
- **读取结果的用途。** 取得的片段作为本次执行的证据单独计量，也纳入模型请求容量校验。Pi 可保留查询过程供审计，后续执行的常驻历史投影和自动交接只使用提炼后的事实与来源引用。索引到期或被淘汰时，来源记录按原有留存规则管理。

## 3. 工作台总结后的历史整理

1. **触发。** 工作台结论通过既有完成门禁并持久化后，在同一事务写入历史整理 outbox，使用工作台、目标、结果版本和需求版本组成稳定业务键。正常完成以及明确接受且有可核实完成事实的结果可以入队。后者须保留缺口状态。直接回答只保存结果记录。阶段性综合、自动续跑中的中间结果和取消只保留原有执行记录，等待可用的完成事实。
2. **整理工作台。** 后台读取上一版历史、当前有效需求摘要、本次已确认结论、验证过的经验和适用的在用进化版本。按章节增量合并，并更新近期依据索引。一次性要求与长期项目偏好分开标注。用户明确纠正时覆盖相应旧条目，无新事实时可以结束本次整理而不产生新版本。进化条目由已生效版本及其适用范围提供，引用失效即从投影移出。整理模型只生成摘要候选，由既有方法学习流程负责采纳或撤回策略。
3. **整理 Joi。** 从同一结论的合格事实生成独立候选。输入只取明确跨工作台的用户偏好及已提炼的通用编排经验。只具工作台权限的材料留在工作台。模型推测的用户习惯不具备提升资格。跨工作台规则的来源、适用范围与后续更正均可追溯，范围无法确认的候选留在来源域。两个更新可独立提交，重试其中一个无需重做已提交的更新。
4. **执行与重试。** 摘要工作在业务完成之后异步运行，独立于 Joi 前台串行编排槽和工作区租约。按作用域串行提交，模型调用在 SQLite 事务外。提交时核对基础版本、来源有效性及当前生命周期。并发更新用最新已提交版本重新合并；迟到结果无法覆盖更新的用户更正。重启可根据 outbox 和处理回执恢复，失败期间继续读取最后一份合规版本。

## 4. 搭档工作结束后的经验

以 **已持久化、权威的 Work 结果**作为入口。搭档在工作结束后用独立小请求整理经验，输入为已有经验、结构化结果及少量经过验证的事实。Pi 默认用本次工作固定的搭档模型版本，不带工具。一次结算可提出零条或若干候选，模型可以判断没有可复用的经验。整理请求与已完成 Work 分开计量，搭档原执行已经结算并释放资源。

建议优先接受经验证的成功方法，以及有明确事实支持的失败教训。取消、迟到结果和副作用未知记录只用于恢复与审计。项目名称、路径、用户原话、个别任务结论、模型思考和工具流水均留在来源记录。经验条目描述方法和适用条件，例如“修改跨平台路径逻辑后分别验证正反斜杠”，可由后台按范围、来源和内容上限验证。

这是一项**跨工作台复用的搭档属性**。以稳定 `partnerId` 保存一份独立可版本化的分节经验，下一次派发读取已接受版本并固定到本次执行。经验写入无需创建新的搭档配置 revision，避免一次结算刷新配置目录、切断常驻会话或使已接收任务失效。任务模型、权限、技能和提示配置由各自的权威配置提供。已禁用或被删除的搭档按现有生命周期处理新经验，迟到更新须复查身份和状态。

结果键去重，运行完成后才允许写。结果同时仍可用于已有的工作台内选人统计。多个工作台的工作并发完成时，同一搭档经验按版本串行合并。推荐首版支持本地 Pi 搭档自行整理，原生 CLI 和 A2A 的处理维持在已有结果事实的权限范围内，后续通过有界结果协议接入。缺少受支持且获准的整理模型时记录安全状态，并保留已有经验。

## 5. 持久化、迁移和生效顺序

历史记录由应用层端口读写，SQLite 基础设施保存每个作用域的当前版本、分节摘要条目、来源引用和更新水位。Joi 层按本地用户配置隔离，工作台层按 `workbenchId` 隔离，搭档层按 `partnerId` 隔离。模型只返回候选；提交时复查来源、范围、有效性及敏感字段。压缩按单条事实独立进行，只采纳更短、合规的候选，并沿用原条目来源。明确偏好、证据引用、在用方法及有稳定主题的条目原样保留。重开、删除、撤回进化版本或修正长期偏好时，失效的条目及索引立即停止注入。诊断只记作用域、处理结果、字数、版本和耗时等安全标量。

1. **先挡住失控请求。** 对 Pi 普通请求和压缩请求做容量校验。回归覆盖摘要超限或失败后普通请求继续发生的路径。容量失败须可识别，避免同一投影自动重复提交超大输入。Pi 可继续使用官方压缩。若需要自定义容量内的压缩请求构造，先验证公开扩展点和固定 SDK 版本，确认摘要及失败语义。
2. **兼容旧会话。** 旧归档与已经导入超大分支的原生日志保留原始记录。新执行在已结算、可安全切换的边界，以有效旧摘要或有界权威目标快照作为种子，关联旧历史供按需查阅。可确认有效的旧摘要才可导入活跃段。当无法确认结算或外部效果时，先走既有恢复和重放安全门禁。迁移使用稳定记录和可重入事务，重启后复用已建立的继任身份。
3. **上线有界整理。** 先接工作台与 Joi 的结论整理，再接搭档经验和各入口读取。历史字段为空时从新结论增量生成。选择性回填仅以近期已确认的摘要和已生效的进化事实为来源，使用与线上同样的范围、容量和资格校验。切换普通聊天读取后，移除同一份内容经旧 `task_summary` 和搭档摘要聚合重复注入的入口。

## 6. 拟议验收

验收使用临时 SQLite、合成会话、固定版本 Pi 和假模型。相应行为在实现前先用回归用例复现失败。以下条目衔接 [AC-67、AC-EVO 与相关恢复门禁](07-roadmap-and-acceptance.md)、[普通聊天的历史与执行段约定](21-normal-conversations.md)和 [Pi 会话权属验收](pi-session-ownership-spec.md)。

| 编号 | 验收条件 |
|---|---|
| HIST-01 | 使用中文和补充平面字符验证三个独立压缩触发值。Joi 自身历史为 5,000，工作台摘要与索引合计为 20,000，搭档经验为 1,000。达到触发值时先尝试压缩旧条目，再附加完整的新条目。压缩失败仍保留原条目和新条目。分节标题计入阈值，空章节省略，各层独立计量。 |
| HIST-02 | 工作台最终总结提交后才产生整理事件。覆盖阶段性综合、直接回答、用户接受有缺口结果、结论重开和旧版本迟到。任何整理故障都不占用前台编排槽或影响已经提交的结论。 |
| HIST-03 | 重放同一搭档结果只生成一次经验更新。并发 Work、恢复和配置修改不造成经验丢失或搭档配置 revision 变化。同一搭档在两个工作台使用同一个经验属性。新 Work 固定经验版本并读取本次必要上下文。 |
| HIST-04 | 两个工作台共享物理目录或搭档时，项目私有材料无法通过 Joi 全局记忆、搭档经验、工具结果或旧会话迁移跨工作台泄露。纠正、撤销或删除后，注入不再包含失效内容。安全诊断不泄露正文。 |
| HIST-05 | 以合成的约 1,500 万字符旧分支复现故障，验证旧归档可查、可用摘要可迁移、正常推理与压缩调用都不会把超预算输入交给假提供方。压缩失败时可以使用有界投影或清晰失败，既有外部执行和已定结论不会因此重放。 |
| HIST-06 | 同一目标连续复查或续跑时，每个新执行拿到当前权威状态和必要结果，同时历史投影保持有界。普通聊天段、历史页面和同一 Work 的 Pi 工具交换可按原权威身份读取与恢复。以相同合成用例比较新旧请求体积、摘要调用次数、更新延迟及失败状态。真实提供方延迟和摘要质量需在实现后另做受控验证。 |
| HIST-07 | 验证工作台在结论发布后即可倒序分页查询，覆盖后台索引尚未写入、接受有缺口、升级前的结果及工作台隔离。Pi 通过 `workbench_read_history` 按引用读取指定版本，受单页、累计证据预算和完整请求容量限制。每次读取使用一致 SQLite 读快照，无需获取写锁或遍历工作目录。后续执行只继承有界摘要及引用，失效或无权引用返回明确状态。 |

## 7. 待商榷的决定

| 决定 | 推荐默认 | 另一种选择及代价 |
|---|---|---|
| 工作台何时积累历史 | 用最终收口作为默认学习时点。长期未收口目标依靠权威需求、结果和有限执行交接继续。 | 每个阶段结论也更新历史，学习更快，临时判断更容易被误记为项目事实，后台成本更高。 |
| 每次 Work 都调用模型整理 | 每次合格结算进入整理流程，先按结构化结算事实判断是否值得调用模型。需要整理时使用搭档本次固定模型。 | 每次均调用可捕获更多隐性经验，增加用量。按批次合并更省，但搭档下一项任务可能读不到刚获得的经验。 |
| 普通聊天纵向会话与跨段交接 | 同段保留用户期望的连续性和 Pi 压缩，跨段继承有界交接和来源引用。 | 对所有聊天轮次使用仅摘要的投影可降低用量，会影响追问、逐句修改和工具交换恢复，需要另行产品验收。 |

## 8. 本地 Pi 首版实施记录

- 采用第 7 节的推荐默认值。工作台总结和 Pi 搭档结算分别触发后台整理，成功结果须有权威版本及验证状态。搭档复盘使用本次固定模型和经过归类的工具结果计数。Joi 全局偏好从明确提到跨工作台适用的用户输入取得，同一主题可用 `全局偏好[主题]` 明确更新。
- 抽取候选只使用本次结算。达到阈值时单独尝试压缩一批已有摘要，再提交新条目和可用的压缩结果。已有条目保留原始来源。同主题的全局偏好按用户输入顺序更新，来源失效后保留顺序水位。
- 工作台原始依据工具提供目标输入和同版本最终结论的分页读取。不传来源时，每页返回最多 20 项已发布结果，使用 `result:` 引用定位不可变的结果版本。完整 `history:` 引用及对应的 64 个十六进制字符继续经过工作台和版本校验。正文每页最多 4,000 个码点，单轮累计最多 32,768 个码点，仍受模型请求容量校验。Pi 在下一执行边界只保留查询记录的引用提示。普通聊天保留本段连续性。跨段交接达到触发值时，较早轮次保留状态、附件及产物引用，详细内容留在来源会话中，最近轮次完整附加。进化条目从当前在用方法渲染。
- Migration 104 添加来源、历史版本及回执，105 保存全局偏好顺序。已有工作台从新合格结算增量积累。旧目标会话保留私有来源，主编排的新执行按业务轮次隔离并可引用旧摘要。历史工具可列出同工作台和同目标会话的前序轮次，按选定轮次分页读取。Pi 搭档按 Work 切分，旧结算可由旧会话恢复。普通推理和摘要请求共用发送前的模型窗口校验。

真实提供方、生产数据升级和安装包属于后续验证范围。原生 CLI 与 A2A 的经验生成由各自的适配器接入。
