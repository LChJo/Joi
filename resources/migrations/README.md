# SQLite migrations

Migration 069 为进化证据增加失败归因。只有上下文整理或完成判断可归因的验收失败进入策略触发门禁；执行、环境和未知原因仍保留在审计证据中，但不会推动策略改写。存量失败标记为 unknown，避免升级后把历史噪声误当作策略缺陷。

Migration 060 增加本地 Token 数值账本：调用身份、各模型累计快照、采集起点与持久缺失提示。按调用内稳定标识替换快照，不扫描历史私有会话，不触发模型请求。

M1 起所有迁移使用单调版本号并在 Runtime 调度前执行。本目录只存生产 migration，不存真实数据库、凭据或测试 userData。

Migration 042 起，普通直接回答写入独立 `joi_turn_completions` 展示投影；Goal synthesis 继续使用带 revision 的 `joi_goal_outcomes`。

Migration 044 起，搭档提问和历史 WAITING 恢复使用 `joi_user_action_requests` 持久关联具体 Work/Run；首页不得再从 `waiting_count` 猜测“需要你”。

Migration 045 起，多个工作台可以绑定同一物理工作目录；工作台上下文仍隔离，文件执行冲突由同目录跨 workspace ref 的 READ/WRITE lease 协调。

Migration 046 起，场景预设包以 `(pack_id, role_id)` 持久绑定全局搭档；重复或部分失败安装复用稳定绑定，用户修改和停用状态不被预设静默覆盖。

Migration 047 起，搭档 revision 可在 `engine_config_json` 保存引擎专属非敏感配置；首个消费者是 Codex 的 sandbox、network、web search 与固定 never approval 权限。旧 NULL 行由 repository 按历史工具列表确定性映射。

Migration 048 修复旧开发库已占用 migration 047 但缺少 `engine_config_json` 的版本冲突；已有该列的数据库只记录修复版本，不重复执行 `ALTER TABLE`。

Migration 049 建立全局 Routine 配置与紧凑运行事实，并为普通 Joi inbox 增加可空 `automation_routine_id`；调度 claim、运行记录和 inbox 输入在同一事务中提交，提示词正文不进入投影。

Migration 050 持久化每个失败 Work 最多两轮的恢复尝试及其权威结果证据引用；补充 Work、dispatch outbox、恢复身份和证据引用在同一事务中提交。

Migration 051 区分可自动补证的 `CONTINUE` 与硬阻断，并为每个目标地图持久化默认两轮续跑额度；额度耗尽后以目标级用户动作提供“继续补齐/接受现状”，接受时保留 `ACCEPTED_WITH_GAPS` 终态。

Migration 052 让声明的 Work 依赖在派发时真正生效：依赖反查索引支撑认领门控（前置未全部完成不可认领），`work_items.cancel_reason` 记录依赖失败/取消触发的确定性级联取消原因。
Migration 054 持久记录每个 Work 的执行目录及准备状态；默认目录使用日期时间与 UUID，绑定目录记录实际目标，恢复、重试和产物解析复用同一记录。绝对路径仅限基础设施内部使用。

Migration 055 为目标保存可空 last_opened_at，仅用户的显式动作（继续/重试、补充回复与回答、续跑决策）更新；首页排序回退 created_at，不再随进度和结果更新时间跳动。

Migration 059 增加 evolution_states、evolution_goal_pins、evolution_evidence。存量已绑定工作台的原始目标固定基线且不采样；新目标保留策略与模型源版本。后台调用使用既有 outbox 的 evolution.model 类型，只含稳定标识，不保存模型正文，且不进入通用出站调度器。预算默认低档预设（每日 50 次调用），迁移不触发历史任务重放。

Migration 063 让上下文窗口、最大输出与压缩触发阈值成为按 model revision 可配置的三个可空列；NULL 即未配置，存量行自动退回厂商 preset 与 provider 实测值，无需回填。表仍是 append-only：一个值要在编辑后活下来，唯一的原因是服务层把它带进了新 revision，仓储从不做 UPDATE 合并。三列的上界刻意排除"压缩阈值 = 100"，那等价于撞满整窗才压缩，而那一刻 provider 已经把 `max_tokens` 夹向 1。

Migration 064 为 partner_runs 增加可空 heartbeat_at：updated_at 的语义是"状态变更时刻"（已被工作台 agent 流当作"最后活动"展示），一个执行一小时却不发生状态迁移的 run 在那里看着像早已停摆，正是活着的搭档与死掉的搭档无法区分的由来。派发 actor 在 run 在途时每 tick 续写这一列，心跳过期即意味着持有该 run 的进程已经不在，这是运行期唯一能把"还在干活"和"已经死了"分开的证据。存量行为 NULL，且 NULL 必须保持旧语义——读取方对 NULL 回退旧规则而非视为过期，否则升级后第一次启动会把所有历史 run 一次性判死。

Migration 065 为目标输入增加可空 reopened_at，显式重试已消费目标或显式恢复隔离评审时更新。它是旧综合结果是否属于当前执行轮次的水位；last_opened_at 仍只负责首页排序，普通回答澄清或授权续跑不能让有效旧结果失效。存量 NULL 保持原有结果有效。

Migration 084 为目标地图增加可空 `review_recovery_epoch`。只有用户显式恢复隔离评审时与 reopened_at 同事务写入，评审身份包含此代次，允许复用同版本证据重新核对。默认 NULL 保留旧评审身份；迁移不更新已有地图、输入、Work、结果或 outbox，不安排历史回合。

Migration 066 为 10 秒 harness/evolution 安全扫描补齐按目标、Work、Turn 和权威结果读取的窄索引。它不改变恢复与回滚节拍；代价是相关状态写入增加有限索引维护和数据库体积，换取历史数据增长后不再反复全表扫描。

Migration 062 增加 `workbench_agent_tool_traces`（工具轨迹私密正文）与 `workbench_agent_conversation_entries.tool_call_id`。主时间线只保留一行 ≤200 字符的脱敏调用摘要；完整命令与输出按 `(run_id, tool_call_id)` 每条追加一次，凭据写入前脱敏、绝对路径保留（本机调试必需）、单条 ≤8 KB 超出截断并标记，只经桌面写权限路由按需读取，不进首页、诊断、SSE 或远端。只登记迁移后的新 run，不回填历史：存量 TOOL_CALL 行既无 `tool_call_id` 也无正文来源。

Migration 061 修复进化证据无法收敛的三处遗留状态，不新增表。为 evolution_evidence 增加 classified_at 承载幂等判定，使证据分类可随目标收敛单调升级，而 observed_at 仍是裁决窗口时间戳、只在真正升级时前移；关闭已撤销（取消 / 忽略）目标上永久停留在 ACTIVE 的清图，撤销时刻取自目标行本身，迁移不依赖时钟；按 059 的实际落库时间精确放行当时仍在途、结局发生在迁移之后的目标，已终结的历史目标继续遵循 059 的"固定基线且不采样"。触发口径改为跨工作台共享证据池见 ADR 0020 的 2026-09-24 修订。

Migration 067 让思考强度成为按 model revision 可配置的第五个可空列（off/low/medium/high/xhigh/max）。NULL 即未配置，存量行退回 baseUrl 白名单判定（always-on 主机 low，其余 off），无需回填。与 063 的三列同属 append-only revision：服务层在保留 Model ID 的编辑里显式携带，改 Model ID 时随三列一并重置——思考档位是"这个模型在这家端点上的事实"，换了模型旧档位可能直接 400。

Migration 068 为目标输入增加可空 `archived_at`，把「归档」做成 `dismissed_at` 的可逆对应物：归档的卡片离开首页信息流、进入「已归档」列表，可在那里撤销归档、继续或移除，因此单开一列而不是复用软删标记。只有终态目标可归档；显式重试与定时续跑在同一次写入里清空该列，重新跑起来的目标不会继续隐身。

Migration 070 增加可空 `continuation_prompt`，将本次用户继续要求与累计展示正文分开持久化；留空继续保存明确的续跑指令。NULL 不改变新目标语义，已存在 reopened_at 的历史续跑回退默认指令。手动继续清除旧 automation_routine_id，避免定时提示词覆盖本次用户要求。已有结论从目标事实按需读取，不复制进 inbox 正文或 transcript。

Migration 071 增加每目标可信输入来源日志、不可变有效需求快照和当前版本指针。Work brief 固定需求版本；运行保存不可变需求投影；综合、评审、用户动作和当前 outcome 投影关联需求版本。旧目标只在下次自然 Joi 编排初始化，既有运行不改写或重放。

Migration 072 在 `model_source_health` 增加可空 `anthropic_auth_mode`；NULL 保持 API Key 行为，`bearer` 仅表示自定义 Anthropic 无工具探测成功后学到的鉴权方式。该事实随健康状态原子比对当前 source/model/credential revision 与状态保存，不修改不可变配置版本或凭据内容。替换凭据或端点重置，普通编辑保留。

Migration 073 为本地任务增加四阶段执行记录、FIFO 写入等待及单调租约代次，并扩展实例状态约束以保留 SUSPENDED。已有 run 的 attempt 固定旧策略；未启动 attempt 默认新策略。检查点引用和独立附件路径仅存私有执行记录，continuation outbox 仅含稳定标识与执行代次，不修改历史结果或引擎权限配置。

Migration 074 为首页按目标关联输入、最新回合、Work 对应实例/run 及可见 Agent 会话增加覆盖索引。查询从目标关联集合开始，保留派生输入最新回合和稳定 Agent 去重语义；不删除历史会话，不修改执行事实。见 ADR 0029 与 AC-PERF-01。

Migration 076 为目标结论建立私有版本历史，按目标、结果版本、需求版本幂等保存，回填当前已有结论；分页取证保留当前与历史结论。结论仅在已有双版本和活动 Work 门禁通过后与发布事务一起保存，不修改正在运行的任务。见 ADR 0031。

Migration 088 为用户正式交付建立独立的不可变结果历史，以完成回合或接受动作标识幂等。事务内触发器仅归档当前且正式结项的完成正文及直接回答；中间综合不进入列表。迁移仅回填当前可核实的完成结果，不从 076 内部综合历史推测正式交付。导出任务保存可空 result_id，绑定历史正文及幂等身份；索引支持按目标稳定分页。见 AC-37/48/57。

Migration 082 更新 Work 插入与归属更新触发器。原始目标尚无 Turn 时，明确关联该原始目标、且输入与 Turn 都属于目标工作台的派生 Turn 也可建立 Work 归属。原始 Turn 的兼容路径保留，跨目标和跨工作台仍拒绝；不回填 Turn，不改变历史任务状态或重放 outbox。

Migration 083 保存方法学习的全局控制、工作台参与选择、调用账本、事实采集回执、不可变结构案例、实验检查点、案例引用、试验缓存及新目标策略绑定。默认共享上限为每日 150 次，只有存在已启用且未暂停工作台时才开启全局控制；各台原有关闭、暂停和子上限保持不变。调用预留与检查点、稳定 outbox 身份原子提交，未知用量可由同一调用的迟到账单补全。版本化读取回执仅登记升级后的真实工具读取；源变化的曝光失效记录不改写首次策略绑定。旧进化历史及目标绑定保留，不重跑任务、不修改真实执行状态。见 ADR 0020。

Migration 085 为 joi_turns 增加可空 review_replay_safe。只有已收尾的失败评审在所有工具均完成且仅包含只读查询、已成功提交的地图事实或明确无修改的事务拒绝时，才与 FAILED 状态同事务写入安全证明；进行中、崩溃及旧回合保持 NULL，已有副作用标记不改写。恢复扫描与写入重验共同限制同一评审身份至多一次自动重核，未知或外部副作用继续隔离。迁移不恢复目标、不重跑 Work 或修改既有问题门禁。

Migration 086 为 joi_turns 增加可空 failure_replay_safe。仅在失败收尾、全部可修改工具都有可信未提交证明且不存在持久派发计划时，与 FAILED 状态同事务写入。恢复查询可以排除带证明的失败回合，但不清除 side_effect_started 高水位；进行中、崩溃和旧回合保持 NULL。SDK 报错及提交后检查点失败不构成证明，取消、问题门禁、已完成回答和活跃 Work 的约束保留。迁移不回填证明或重放历史任务。

Migration 087 为 joi_inbox_messages 保存回合失败计数、最后失败时间与安全原因、下次尝试时间、会话代次和显式继续的重试代次。失败收尾与计数同事务，旧失败重复投递不再次计数；显式继续清除预算与退避并递增重试代次，保留会话代次，旧回合不能改写新继续请求的重试状态。新增列默认空预算，不推断历史副作用、自动重放或迁移任务状态。见 AC-67。

Migration 089 从工作结果的既有产物清单建立可分页的元数据读索引，并用同事务触发器维护新增、更新及删除。索引只接纳有效工作区相对路径及文件元数据，排除版本控制和依赖目录；原始清单和文件保持原样，文件打开标识保留来源结果ID及原数组下标。读取时按目标和当前权威结果去重，首页最多20条预览，完整列表独立分页，不在轮询中解析全部历史JSON。见 AC-PERF-01 / AC-37 / AC-57。

Migration 090 为每个产物来源及学习事实读投影维护同事务不透明版本标记，供有界内存缓存识别相关写入。来源清单变化更新来源标记；学习标记只覆盖事实和资格判断依赖的数据，不受凭据、会话心跳或单独产物清单更新影响。回填仅新增元数据，原结果、文件、历史及打开ID保持不变；回滚后的后续写入不复用已中止标记。见 AC-PERF-01 / AC-EVO-01..08。

Migration 091 为正在运行的 Turn、前台 Work、非终态派发尝试与 Run、未销毁实例建立部分索引，并补充 outbox 到派发尝试的反向查找。索引支持按当前活动集合及到期队列读取，保留原调度周期、依赖、门禁、恢复和原子认领语义；迁移不改写业务记录或重放任务。见 AC-PERF-01 / AC-EVO-03。
