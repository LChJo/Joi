# Pi 摘要机制复盘与优化方案

日期：2026-11-12。状态：两批实现与本地质量门禁已完成。初始复盘基于代码/官方契约核对、合成探针与 20 项历史预算基线测试；以下问题描述记录的是优化前行为。真实模型对话复测尚未执行。

## 问题与证据

代码分析对话的安全诊断覆盖 17:20:52–17:27:35，共 403.273 秒。13 次实际 bash 合计 4.165 秒；普通模型请求 43.013 秒；10 次摘要请求合计 352.457 秒，占 87.4%。应用层摘要失败 9 次、取消 1 次，没有成功压缩记录。摘要候选从 488749 增至 529707 字符。context_prepare 包含摘要等待，不能与摘要耗时相加。

飞书对话是另一种负载：其主要耗时在长 bash 内部。两组诊断不能合并归因。

当前执行链：达到历史软目标或容量条件 → 在请求准备中同步生成摘要 → 校验结果与净节省 → 成功才推进检查点 → 失败保留已有检查点并构造有说明的降级请求。新工具结果会改变摘要候选；候选变化可绕过旧候选的 30 秒退避。

### 已确认的设计问题

1. **软触发同步阻塞。** 历史达到 128000 字符软阈值即可在下一次工具后的请求准备中等待模型；容量尚有余量也会付出完整摘要时间。失败后又以 64000 字符软目标组织尾部，下一轮仍对保留的完整原文重新判断。
2. **重试身份混合了两个职责。** 内容指纹适合验证摘要覆盖是否正确，却不适合独自决定模型连接是否该再次尝试。新增少量工具输出就可能解除上一次失败的保护。
3. **SDK 输出预算语义发生分离。** Pi 1.5.2 的摘要 reserveTokens 参数已不承担摘要输出上限；Joi 的适配回调仍将 maxTokens 强制设为传入 reserveTokens。Partner 路径进一步将其限制到最多 8000；主 Joi 的摘要配额也由摘要字符目标间接换算而来。
4. **结果与错误信息不足。** SDK 拒绝 length 和工具调用响应；Joi 将其和普通请求异常统一折叠为 Error。请求完成指标没有表达摘要是否被接受，无法判定线上 8 次完成的模型请求具体为何没有形成检查点。
5. **helper 终止校验不完整。** 合成探针中，外层 signal 未取消而响应 stopReason 为 aborted 且带文字时，helper 返回成功。常规外层 signal 检查仍有效，但不能代替响应状态校验。尚未证明线上出现了该情况。
6. **首次积压没有输入批次上限。** 没有新检查点时，一次失败可能再次处理约 50 万字符，而非稳定推进一段已冻结的源前缀。

### 本轮验证与根因界限

使用已编译的当前生产 helper、真实 Pi SDK 表面和 fauxProvider，模型窗口为 1000000、声明输出上限 32768，传入 reserveTokens=8000：

| 合成响应 | 当前 helper 结果 | 实际请求输出上限 |
| --- | --- | ---: |
| stop | 成功 | 8000 |
| length | 失败，Error | 8000 |
| error | 失败，Error | 8000 |
| toolUse | 失败，Error | 8000 |
| aborted 且带文字，外层未取消 | 成功 | 8000 |

失败后虚拟时间推进 1 秒：同候选剩余退避 29000 ms，新候选为 0。现有历史预算回归 20 项通过，其中一项明确要求内容变化后立即重试。这说明优化需要修订原有策略及对应测试。

以上确认了失败放大机制和协议缺口，**没有确认线上 Error 一定来自 length**。生产归因必须依赖新增的安全终止分类，不能记录原始异常文字或摘要内容来代替分类。

## 方案取舍

| 路径 | 判断 |
| --- | --- |
| 仅提高摘要输出上限或历史阈值 | 无法修复不完整响应校验与跨候选重试；扩大上限还可能增加失败成本。配额必须修正，但不是完整方案。 |
| 直接启用 Pi SDK 自动摘要 | 需要重新划分原文持久化、会话投影、覆盖与取消的所有权。当前宿主已有一套检查点策略，同时启用两套会有冲突；应作为独立迁移评估。 |
| 共享结果契约和重试策略，再把软摘要后台化 | 复用当前原文、检查点和模型连接，可分批验证正确性与等待时间，采用此路径。 |

## 确定方案

采用一个共享摘要策略，分两批交付：先修复结果契约和失败重试，再将软触发移出请求等待路径。主 Joi 与 Partner 复用策略和结果分类，各自保留会话存储及调度所有权。

### 第一批：修复正确性与失败放大

1. **严格判定可接受结果。** 只接受正常完成、无工具调用且有有效正文的响应；length、aborted、pending、工具调用和错误响应均不得推进覆盖。取消与失败分别处理。
2. **使用安全的结构化结果分类。** 区分截断、取消、供应商失败、工具调用、空结果、输出过大、无净节省、超时及未知适配异常。记录终止类别、耗时、输入/输出规模和配额；token 计数只能通过事件专属的有限非负数字白名单。保留模型请求完成与摘要接受两个事实。
3. **拆开容量预留与摘要输出预算。** 按固定版本 SDK 的语义计算摘要输出配额，计入完整摘要请求、已有摘要、指令、模型输出上限和余量；不再把 reserveTokens 直接作为 maxTokens。摘要按模型能力默认不启用额外推理，以实际出站参数的合约回归确认，不能只依赖调用层的 off 标记。继续使用本轮已固定的模型连接及凭据边界。
4. **失败保护独立于内容候选。** 在私有执行会话及模型连接 revision 范围内维护失败状态。连续失败后的冷却默认依次为 30、120、300 秒，后续保持 300 秒；仅成功接受摘要才清零。新增工具结果、READ/WRITE 阶段切换和普通“继续”不清零。模型连接 revision 真正变化后重新评估。
5. **候选冻结与去重。** 摘要开始时冻结源前缀、覆盖起止、前一检查点和模型 revision。同一会话最多一个在途摘要；尾部追加不创建第二份相同前缀任务。内容指纹继续用于验证覆盖、去重与丢弃过期结果。
6. **异常不推进检查点。** 旧摘要、原始历史、原权限、当前任务锚点和最后完整工具交换继续保留。截断、空结果、取消或无净节省都不能被记成成功压缩，也不能触发原业务工具重放。

冷却元数据复用私有执行会话存储，需覆盖恢复、权限阶段切换和迁移兼容。取消不累加失败，也不清除已有冷却或连续失败计数；同一次取消不能被自动转换成新的摘要尝试。统计模型账单的完成状态不因摘要被拒绝而被伪造。

### 第二批：降低请求等待与单次摘要成本

1. **区分软目标与硬容量。** 先保留现有 128000/64000 字符作为软策略，避免同时改变全部触发参数。软目标只申请后台摘要；请求仍能容纳完整历史时，保留完整历史继续执行。完整提示、工具、锚点、已有摘要和输出预留共同决定硬容量，最终容量断言继续有效。
2. **软触发不等待生成。** 请求准备只收取已完成、校验通过的结果或登记摘要工作，不等待模型生成。后台摘要由现有引擎会话持有，不创建新的全局调度者、业务队列或子代理。
3. **硬容量采用有界恢复。** 优先使用已有检查点和仍完整配对的尾部；可等待正在进行的摘要最多 5 秒。仍不能容纳时使用现有明确说明的降级投影，受保护内容仍超容量则明确失败。不得为了满足时限静默裁掉任务、约束或最新工具交换。
4. **限制首次积压的输入批次。** 常规每批以不超过 64000 字符及模型可用输入预算中的较小者为目标，在完整消息/工具交换边界切分，成功一批就验证并推进对应源前缀。已有摘要作为更新上下文，后续仅处理未覆盖段。单个不可拆工具交换超过软批次时，必须按硬容量单独处理或明确返回容量类别，不能虚报整段已覆盖。
5. **将目标长度与生成上限分开。** 初始摘要目标不超过 8000 字符，是压缩策略目标；实际生成配额由输入余量和模型能力确定。超长或 length 响应不截字入库，按安全失败路径处理。单次摘要默认生成期限为 60 秒，作为初始运行策略记录并复测，不能据此承诺外部模型响应时间。
6. **安全提交后台结果。** 追加尾部允许复用被冻结前缀的摘要；只有源前缀指纹、覆盖父检查点、模型 revision 和执行代际仍匹配，且最终投影有净节省时才接受。回滚、原位编辑、路由变化或取消后迟到的结果不得覆盖新状态。结果在会话拥有者的准备/收尾边界持久化；关闭或停止时取消并收拢在途工作。

5 秒等待与 60 秒生成期限属于不同预算：前者限制硬容量恢复对主请求的等待，后者限制后台调用生存期。软触发不消耗这 5 秒。后台请求因结束/取消而停止时，模型连接的实际取消收尾仍应测量并遵守既有等待语义。

结果提交使用会话执行代际，与工作区 READ/WRITE 的权限 generation 分开。同一用户轮次的 READ→WRITE 续跑共享摘要在途身份和冷却；新轮次、停止、回滚或模型 revision 变化需要校验旧任务的提交资格。权限阶段变化不会授权摘要改写当前系统策略。

## 用户需求

1. 简单工具完成后能够继续下一步，避免每条工具后重新等待同一段历史的摘要。
2. 摘要暂时不可用时，保留已有检查点和可读取的完整原文。
3. 当前任务、要求、权限和最近工具结果在压缩前后保持可用。
4. 截断或取消的输出不会被误认为完整记忆。
5. 长历史逐段推进，已成功处理的前缀不会反复全量发送。
6. 新增工具结果不会解除模型连接的失败冷却。
7. 停止操作会取消后台摘要，迟到结果不会改变已结束的会话。
8. 恢复会话、权限阶段切换和模型 revision 变化具有明确的状态规则。
9. 通过安全数字和类别定位失败，避免暴露正文、推理、路径或凭据。
10. 无法在安全容量内继续时得到明确结果，而非虚构覆盖或重放未知动作。

## 实现决策与测试接口

保留现有上下文管理接口和原始历史读取接口作为外部 seam。共享摘要 helper 负责 SDK 适配、预算与结果分类；私有会话内的摘要协调逻辑负责候选冻结、在途去重、冷却和结果提交。两个 Pi 运行路径复用同一策略；各自的应用服务继续拥有权限、持久化及执行生命周期。

使用现有真实 SDK + 合成模型连接的测试方式，通过最终请求、检查点、私有会话保存和安全诊断观察行为。优先扩展现有历史预算与会话合约回归，不引入只验证内部字段排列的测试。

第一批可以独立验收：错误可区分、无效结果不入检查点、内容变化不突破冷却；它仍可能为一次合法摘要等待模型。第二批验收软触发不等待模型，不能用第一批完成来宣称已经消除了请求路径上的摘要等待。

## 拟新增验收条件

实现与测试按以下标准验收；完整门禁和真实模型复测的完成状态单独记录，不将合成验证等同于模型回答质量验证。

| ID | 验收 |
| --- | --- |
| SUM-01 | stop/length/error/toolUse/aborted/pending/空结果均有真实 SDK 合约回归；外层 signal 未取消的 aborted 也不生成检查点。 |
| SUM-02 | 模型请求结束和摘要被接受分别可观察；诊断类别明确且没有正文、路径或原始异常文字。 |
| SUM-03 | 首次失败后，30 秒内新增或修改 20 个候选仍不发第二个摘要请求；连续失败执行 30/120/300 秒冷却，恢复会话和 READ/WRITE 切换不解除冷却。 |
| SUM-04 | 用虚拟时间回放本次约 403 秒、单次失败约 40 秒且持续追加工具输出的形态，默认策略至多启动 3 次摘要请求；任何时间至多一个在途请求。 |
| SUM-05 | 合成摘要延迟 40 秒时，软触发的主请求在摘要未完成前继续；测试用可控 Promise 和虚拟时间证明，不依赖真实服务的秒级阈值。 |
| SUM-06 | 硬容量等待至多 5 秒，随后进入有说明的安全降级或容量失败；受保护内容和完整工具交换不被静默截断。 |
| SUM-07 | 约 50 万字符积压按批次推进；每批完整，下一批始于已接受覆盖之后，首批成功后不重读已覆盖前缀。 |
| SUM-08 | 仅追加尾部时可安全接受结果；原位编辑、回滚、更新检查点、模型 revision 变化或取消产生的迟到结果不能提交。 |
| SUM-09 | 原始历史、已有摘要、当前任务锚点和分页读取保持；失败/无净节省不推进覆盖，不重放业务工具。 |
| SUM-10 | 摘要预算计算包含完整请求及输出余量，中文、长工具结果、小窗口模型均有回归；超大单个工具交换具有明确容量行为。 |
| SUM-11 | 请求数量、失败类别、重试等待、输入/输出规模、摘要等待及取消收尾均可观测；阶段有嵌套时不重复计入总耗时。完成或取消后不得残留“正在摘要”状态。 |
| SUM-12 | 各批实施先添加并运行失败回归，完成类型、lint、测试、覆盖率、端到端、生产构建、包验证和架构边界门禁，再用真实对话复测延迟和连续性。 |

## 文档与兼容变更

实施第一批时需同步修订 CHAT-20、ADR 0033 和既有“内容变化即可立即重试”的回归预期。保留其取消、覆盖校验和原文保留要求。第二批需记录软/硬容量、后台工作归属、迟到结果与关闭语义。旧检查点和没有冷却元数据的私有会话必须可读；不触发历史业务重放。

候选批次、目标长度及期限是初始策略值；调整须依据可复现指标，保持安全不变量。后台运行可能增加瞬时并发和主请求的原文输入量，需比较模型请求耗时、用量及答复连续性，不能只看工具间隔。
