# Joi 增量知识与定时任务留存

状态：分阶段实施。首批已接入定时续跑的有界结论、Joi 与工作台的新结算采集、目标搭档展示上限，以及实际执行轮次编号。

## 目标

同一条 Routine 可以持续运行。历史搭档和调度轮次增加时，新执行的上下文上限保持固定。已经沉淀的知识可以直接使用，知识的查询、更新和目标复查均无需读取旧搭档正文。每次结算只处理本次新增事实和受这些事实影响的知识条目。

目标详情最多加载 100 个最新搭档执行。更早的执行用阶段汇总和知识入口呈现。每条 Routine 保留最近 200 个实际调度轮次的执行明细，超出窗口的明细从本机受管存储删除，迟到事件和历史扫描均无法重建它们。已经确认的知识、仍有效的业务检查点和聚合统计可以独立存续。

「无限上下文」指系统持续运行时，单次模型请求、增量处理量和定时执行明细的留存窗口有界。独立且长期有效的知识可以增长，按需检索。用户想逐字找回的旧正文需要在有效留存期内查看或主动导出。

## 1. 持久化边界

| 数据 | 写入时机 | 读取与留存 |
| --- | --- | --- |
| Routine 检查点 | 一页源数据确认处理、待办持久化、外部动作结算时 | 按 Routine 和数据源保存扫描位置、当前有效要求版本、待处理项及待核对回执。恢复直接读取检查点。 |
| 权威结算事实 | 当前 Work 或调度运行结算时 | 保留有界的结论、适用范围、验收项、检查结果、缺口和必要来源标识。仍被业务引用的验收事实独立保存，其他事实随留存窗口清理。 |
| 知识条目 | 本次产生新事实、验证了适用条件，或用户更正时 | 保存可直接理解的结论、适用条件、验证种类、权威等级、版本和精简出处。按当前授权和适用范围检索。 |
| 执行明细 | Turn 或 Work 执行期间 | 包括会话、结果正文、交接、消息投影、工具轨迹及临时文件。仅用于当前执行和留存期内的明细查看。 |

知识沿用 Joi、工作台、搭档三种作用域。项目结论、源码版本和本次故障根因归工作台。搭档只保留经确认、可跨工作台复用的方法和验证经验。Joi 全局只保留明确通用的偏好和编排经验。权限检查读取当前知识归属与授权。原 Work 过期时，来源标识仍可说明知识来自哪次已确认结算，无法通过该标识反查正文。用户更正、撤销授权或删除知识仍能使条目失效。

正式综合判断必选需求时使用与需求版本、适用范围和具体验收类型绑定的结构化检查事实。普通摘要、自述结果或非空正文检查只能证明其实际覆盖的事项。若旧检查已失效或缺少必要事实，显示缺口，必要时安排新验证。永久留存的事实应能说明检查了什么、用什么验证、结果及限制，无需重新打开旧报告。

## 2. 结算与知识更新

1. 当前执行提交有界结构化结算。业务校验结论、验证结果、来源、外部动作状态和适用范围。提交缺少依据时保留相应缺口。结算事务同时落下稳定事件标识和待处理记录。后台整理可以延迟或重试，输入始终是这次已结算的结构化内容。
2. 用作用域和业务主题定位知识。处理新条目、更新旧条目、标记冲突或撤销已有结论。完全相同的事实直接结束。用户更正优先，迟到的低权威结果不能覆盖新版本。一条旧知识有多个支持来源时，失去一个来源后按剩余的有效依据判断。无新增信息的空扫、重复回执和重试不调用知识整理模型。
3. 整理器只读本次有界结算和命中的有界知识条目。多个更新合并在同一主题版本上，冲突时重试受影响条目。若一个主题积累了过多互不相同的事实，按已有业务实体和条件细分，保留当前有效内容与必要的冲突状态。更新索引和更新知识使用同一提交，避免需要周期性全库重建。
4. 新回合以当前要求、Routine 检查点、未完成项和少量相关知识启动。检索按授权、主题、适用版本和相关性限量返回，同时受独立 Token 预算约束。Joi、Pi 搭档、原生搭档、A2A 和复查都使用这个业务投影。现有路线图负责定位当前活跃工作、有效证据和已沉淀知识。历史详情入口与模型使用的知识读取入口分开。

以飞书扫群为例，新一轮只读当前扫描范围、上次确认的位置、本轮待处理项和命中的处理方法。如果新增话题和未响应的明确提及都为空，保存扫描进度并静默结算。发现新增时，按源消息稳定标识分派调查，附上本轮的附件、反馈和源码检查结果。有回复需求时，同一消息复用同一动作标识。回执不确定时先核对原话题，不能证明是否发过时记录待核对状态。外部系统会重放旧事件时，用稳定来源序列、原始消息标识和可验证回执拦截重放。确有长期去重要求的业务回执独立保留，与旧搭档执行明细无关。

## 3. 最近 100 个搭档与阶段展示

- 100 指目标内最近有活动的搭档执行卡。用目标范围内的活动顺序与稳定标识排序，服务端投影先取至多 100 个标识，再加载卡片数据。复用现有搭档的资料页和授权入口。首屏、刷新、搜索与分页都不能通过目标面板加载第 101 张执行卡。
- 先显示最近执行，再显示按用户可理解的阶段聚合的历史，例如「第 1–32 轮 · 已沉淀 12 条知识」。聚合采用已提交计数和阶段结论，空扫只更新运行计数。每个阶段用少量条目显示有效结论和未解决事项，旧路线的展示转为汇总。知识详情可以搜索和分页，响应中只返回知识及状态，不构造逐个旧搭档的占位或会话入口。
- 排在第 101 位及以后的执行在目标详情中统一显示阶段和知识。旧目标链接进入同一视图；过期和无权限的执行明细均不可访问。若当前有待确认事项，使用现有待办和问题入口显示，即使对应执行卡掉出前 100 也能处理。阶段切换与刷新沿用目标选择与滚动状态。

## 4. 最近 200 个调度轮次与清理

每条 Routine 独立分配单调递增的执行轮次。进入实际执行才分配编号。同一调度的重试、恢复与被合并的触发共用编号。目标被多条 Routine 使用时，分别计算各自窗口。到第 201 轮时，第 1 轮进入清理范围。窗口按轮次计算。普通对话、独立的手动任务和通用搭档配置不参与这个窗口。

新轮次进入前，确认即将退役的轮次已结算或已完成安全移交。当前的待办、未确定副作用、审核和恢复所需事实须迁到独立业务记录。源明细仍是唯一恢复依据时，暂停该 Routine 的下一轮并显示阻塞原因，直到可以安全释放。知识提炼本身不阻塞退役。届时未提交的候选直接失效，已提交的权威事实仍可读取。

清理分两个可恢复阶段。

1. **关闭旧执行的写入入口。** 按 Routine 推进单调的退役水位并提交清理任务。知识收集器、执行回调、重试、恢复扫描和备份导入都检查归属和轮次。迟到的正文、结果及尚未提交的知识候选均不能入库、重新排队或重新提炼。收集写入和水位推进在提交时互斥，关闭后旧任务只能安全结束。按 Routine 保存水位即可阻止整个旧范围重新进入。
2. **清除所有受管副本。** 在有界批次内解除对旧执行的引用并删除 SQLite 行，随后清除该轮的受管私有会话、结果正文、交接、工具轨迹、临时产物和缓存。多轮共享的搭档配置、会话载体及产物需要按实际所有权处理。对仍有活动引用的载体先隔离或拆分目标轮次内容，避免级联删除当前任务。仅保留独立知识、业务检查点和阶段统计。文件清理由持久任务追踪，失败后继续重试。SQLite 页回收和受管备份轮换单独验证。恢复旧快照时应用仍在的最新退役水位；如果该水位也已遗失，隔离导入的旧执行，禁止自动收集。用户手动导出的副本与外部系统记录由其各自所有者管理。

应用使用知识时，知识条目通过自己的版本、权限、验证事实和撤销状态判断有效性。现行历史来源校验和综合证据覆盖仍依赖原始执行关系，迁移必须先让独立知识和检查事实承接这些约束，再允许删除对应来源。

## 5. 迁移顺序

1. **先写独立知识和检查点。** 新结算增量写入，在影子读路径对照既有业务结论。旧数据只迁移已经保存的结构化结算、有效摘要和可核对的验收元数据。缺乏依据的条目标记待验证。升级时不扫描或重新总结旧执行正文。
2. **切换读取和展示。** 将续跑、综合、搭档和历史整理切换到有界知识与当轮证据。目标面板启用 100 张执行卡和阶段汇总。先以只读方式预览退役轮次、未迁移引用、受管会话文件和阻塞原因。
3. **启用退役和清理。** 先验证回调、外部回复恢复、备份恢复及权限行为，再启用真实清理。旧执行若缺少可证明的 Routine 归属和顺序，先单独报告。待可靠重建归属或应用明确的旧数据迁移策略后，再进入清理窗口。

## 6. 验收

| 编号 | 可验证结果 |
| --- | --- |
| KN-01 | 历史分别为 10、1,000、100,000 个执行，固定本轮 3 个新增事实和相同命中知识。首次模型请求与整理器读取的数据量在同一限额内。SQLite 授权器与私有存储替身同时拒绝旧正文读取，续跑、综合、Pi、原生和 A2A 仍能使用已沉淀的知识。 |
| KN-02 | 重送同一结算、并发提交同一主题、用户更正后收到迟到结果。每次增量最多生效一次，其他主题不被重写，旧结论不能复活。撤销原工作台权限后，相关知识和检查事实无法越权读取。 |
| KN-03 | 同一目标提供超过 100 个执行和多个历史阶段。首屏、刷新、搜索、翻页都最多加载最近 100 张执行卡；历史阶段只读取聚合和有界知识页。第 101 张执行掉出列表后，尚待回答的问题仍可从原入口处理。 |
| KN-04 | 单条 Routine 从第 200 轮进入第 201 轮。第 1 轮的受管明细和私有文件在清理完成后不可检索。其已确认知识、验收覆盖和聚合统计仍可用。插入迟到事件、恢复旧 outbox、崩溃后重跑清理，各入口都无法重新创建旧执行或重新收集它。 |
| KN-05 | 继承一个含 1,000 个旧结果的扫群任务，连续空扫多轮，再加入一条新话题和一条未响应的明确提及。空扫只提交水位与计数，无旧正文读取、无新调查 Work、无知识整理调用。回复后重启，两条新增各最多有一次已确认回复；回执未知时进入核对流程。 |
| KN-06 | 跨 Routine、共享搭档、遗留无归属数据和备份恢复均在隔离库验证。清理只影响可证明属于退役轮次的明细，未结算副作用和当前待办保有恢复路径。中断清理后重启，删除可继续，已关闭的收集入口保持关闭。 |

与 [历史上下文策略](historical-context-policy-spec.md)、[总结与复查取证规格](joi-review-evidence-spec.md)、[Routine 调度 ADR](adr/0014-routine-single-joi-scheduler.md) 共同评审。本草案拟细化现有 HIST-01–07、REV-01–08 与 AC-63 所覆盖的边界，KN-01–06 是新增拟议门禁。

## 首批实施范围

- 定时续跑启动沿用目标已保存的结论、决策和雾区，不自动读取旧 Work 正文。手动续跑和正式综合保留各自的证据契约。
- Joi 和工作台的新结算在原结算事务内保存有界结论、需求快照及明确偏好。后台整理可直接取用。这批记录仍沿用既有的来源生命周期校验。旧版本待处理任务使用兼容读取。
- 目标详情服务端先按目标内活动选取最近 100 个搭档，再加载卡片。按目标读取的明细和分页共享该范围。
- Routine 在首次进入执行时分配独立编号，由同一执行的重试复用。未执行的调度和无可靠归属的旧记录没有编号。存储层历史查询最多返回最近 200 条运行记录。清理尚未启用。

主题化知识索引、Pi 搭档结算和其他引擎的统一投影、历史阶段入口、Routine 扫描检查点和静默结算、退役水位及清理是后续阶段。启用清理前须先证明已沉淀的知识与验收事实能够脱离旧明细存续。
