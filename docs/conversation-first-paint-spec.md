# 对话与搭档详情首屏性能修复

普通对话挂载时，工作台、历史、模型源和搭档四个请求一起提交结果。慢目录会推迟左栏历史和已选对话的读取。现有搭档详情接口同时读取消息和完整卡片，打开详情会等待执行状态、等待原因和结果评估的查询。

前期受控复现中，历史和工作台在 20 ms 返回，搭档目录在 1,000 ms 返回，历史列表在 1,000 ms 才显示。临时 SQLite 按同一目标读取 50 条搭档消息时，500、5,000、20,000 次合成执行对应的中位耗时分别为 1.6、14.9、82.0 ms。数据库计时与用户可见耗时分开记录。

## 普通对话

- **CHAT-PERF-01**（CHAT-01/02/13/46） 工作台与历史可在模型源、搭档和 Skills 加载期间显示。左栏区分初次加载、成功空列表和失败，可重试失败的左栏读取。成功的工作台和历史摘要按 API 会话在内存保留，返回页面先展示这些摘要，再刷新。
- **CHAT-PERF-02**（CHAT-02/04/46） 已接受的上一条会话按 ID 立即恢复。切换历史或新建时取消旧读取，过时响应无法修改当前会话。已归档或删除的会话回落到新草稿。暂时读取失败时可以重试。
- **CHAT-PERF-03**（CHAT-03/04/06/46） 网络与搭档分别加载，用户已选配置优先于初始化默认值。技能目录在打开选择器时读取。发送仍要求适用的工作台、搭档与网络就绪。历史搜索、改名、归档及删除使用当前摘要，慢刷新无法撤销已经成功的操作。

## 搭档详情

- **CHAT-PERF-04**（AC-37/57/60/61、CHAT-16/17） 消息首屏和向上翻页使用现有只读接口的可选 `view=messages`，返回 `items` 和可选 `nextCursor`。默认接口仍返回完整卡片和消息，保持既有客户端兼容。两种读取共用游标、分页限制、消息安全投影和工作台、搭档、目标归属规则。
- **CHAT-PERF-05**（AC-57/60/61） 首屏使用已显示的卡片状态。运行中记录在首屏之后刷新消息与状态；刷新补齐错过的消息页，终态收尾保留最终输出。已完成记录打开时只读取消息，继续支持历史翻页、产物和授权工具详情。
- **CHAT-PERF-06**（AC-60） 消息模式验证可见会话和目标归属后沿消息顺序索引取页。首屏避免卡片的执行状态和结果聚合。用 SQLite 查询计划验证关键读取，必要时增加面向会话归属的索引。

## 验收

- 用可控请求分别推迟配置、已选对话和历史，验证各自的渲染时机、真实空状态、失败重试、切回页面和旧响应隔离。
- 用临时库校验消息模式的最新、较早页、范围隔离和脱敏。验证 50 条消息的查询路径，比较不同执行规模下完整模式与消息模式的耗时。
- 运行相关组件、HTTP 契约、SQLite 测试和 TypeScript、定向 ESLint、架构边界检查。桌面实测用点击到历史可见和点击到首条消息可见两个指标。

## 合成数据验证

同一个临时库、同一常驻搭档与目标、同一页 50 条消息。两种模式分别读取 11 次，记录数据库仓储耗时的中位数。

| 同一目标的执行记录 | 完整模式 | 消息模式 |
| ---: | ---: | ---: |
| 500 | 2.29 ms | 0.35 ms |
| 5,000 | 26.45 ms | 0.25 ms |
| 20,000 | 128.89 ms | 0.40 ms |

执行计划用现有索引查会话、限制目标归属和按顺序读取消息。目标过滤按消息所属运行逐条查找，无需预先列出该目标的全部运行。本次复测未触发新增索引或迁移。耗时仅涵盖合成库读取，桌面可见耗时需单独测量。
