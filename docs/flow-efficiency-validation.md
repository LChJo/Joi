# 现有流程效率优化与分模块评估

日期：2026-10-19。范围：现有 Wayfinder、搭档交接、会话压缩、综合、记录与受限进化。没有引入新执行框架，没有降低思考等级或增加固定任务截止。

设计取舍参考 [Google Harness² 原文](https://arxiv.org/html/2610.14224v1)：本项目吸收执行对照、条件化经验和成本评估思路，落到现有受限进化；没有把研究中的优化循环加入每个用户任务。

## 摘要何时生成

| 处理 | 触发与身份 | 是否占用用户任务关键路径 |
|---|---|---|
| 搭档语义交接 | 搭档正常完成时，与完整交付正文同一模型回合生成 | 属于原完成调用，无独立总结调用 |
| 会话容量压缩 | 可摘要历史达到软预算或真实窗口需要；相同覆盖范围复用检查点 | 容量不足时才等待；保存时采纳已有检查点 |
| 目标综合 | 当前结果版本、需求版本有变化；同一版本自动幂等 | 属于目标交付；显式重试使用独立恢复代次 |
| 搭档长期记忆 | 首条及累计每 8 条；水位与稳定结果回执去重 | 空闲后台单并发，不阻塞 Joi 综合 |
| 策略进化 | 既有预算、可归因证据和评测条件满足 | 保留原有受限评测调度，不增加每个任务必经环节 |

因此，“一次目标综合”不等于“整个任务终身只能调用一次模型”：新证据或新要求可以形成下一轮综合，用户显式重试也应可达。控制的是同一证据/需求版本的重复自动处理，以及同一历史范围的重复压缩。历史 118 秒回合的耗时不能直接当作本轮修改后的实测结果。

## 交付与证据

| 模块 | 行为及可验证收益 | 质量边界与复盘 |
|---|---|---|
| 搭档交接 | Pi 终态工具、Claude/Codex 同 SDK 回合结构化正文与交接；A2A 消息/产物 DataPart 兼容 | 预览与语义交接分离；无效或缺失可回读；内部 JSON、状态不进入展示，验收独立 |
| 目标综合 | 当前要求、上次状态及有界变化页；同版本去重；冲突、缺口和证据引用持久保存 | 跨目标/未来版本引用拒绝；旧需求或未知范围不盖验证；分工范围允许并集支持；大状态及首屏省略可补读 |
| 会话压缩 | 200K 合成工具循环从两次摘要降为一次；重建无新增时不重复摘要 | 保留首尾任务、完整工具交换和归档；摘要失败、空白、超容量不推进覆盖；回滚保持原文和覆盖一致 |
| 查询与保存 | 索引每页最多 8 条、SQL 最多取 9；变化页 16 条；Pi 启动只取显式/依赖证据和最多 8 条可选候选；1000 条归档迁出 metadata，不变保存零写入 | 数字旧游标兼容；孤立正文引用不截断后续结果；Unicode 完整；原生完整 catalog 保持可用 |
| 搭档记忆 | 40 条结果由 13 次摘要降为 6 次，增量输入总计 40 条 | 稳定结果去重、原子 outbox、覆盖水位单调；模型挂起不阻塞前台，空闲让行、单并发及续租 |
| 受限进化 | 同场景对照确定性提取经验，相关项最多 4 条；全部重试/中断计入成本 | 同时约束调用数与 Token，保留开发/封存分离、灰度/回退；未扩大自主改动范围 |

## 验证方法

所有数据库、工作区及原生 CLI 配置均为临时合成环境；没有读取真实 userData，也没有停止、安装或重放真实任务。

- 领域与适配器测试先观察失败再实现；补充端到端投递/持久化、引用和需求范围、同版本重放、后台阻塞及失败恢复回归。
- 历史 10/100/1000、固定新增 3 条，验证模型背景保持既有预算、仅携带增量且正文可追溯；数据库首屏不加载全量历史正文。
- Pi 启动夹具在 10/100/1000 条无关历史下读取最多 12 行正文；显式引用及多层依赖保留，全部历史仍可分页访问。SQL 对必要候选取最多 60000 码点、可选候选取最多 12000 码点的头尾片段，完整中段经原读取端口访问；仅取目录的验收路径完全跳过证据构建。
- 真实 Pi 工具结束事件经 coordinator 提交到临时 SQLite，单模型回合保存冲突、缺口和证据状态，公开事件及诊断不出现私有内容。
- 原生 CLI 使用本机回环模型替身，证明 schema 到达实际 CLI 请求，完整正文与交接在同一供应商回合生成；独立模型凭据及真实外部副作用不参与测试。
- 诊断只包含安全 ID、状态、数量、覆盖水位和耗时，交接、私有状态及记忆正文不进入诊断或公开事件。

## 自审中修正的明确缺点

1. 请求与保存摘要覆盖不共享；任务锚切换可能丢原任务；空白摘要误作成功。
2. 记忆裁剪后计数持续为 32；积压重复输入旧账本；降级摘要可能覆盖旧经验。
3. 分页虽限制响应但仍全量读取；生产工厂未透传分页接口；孤立正文引用造成分页截断。
4. Claude 内置结构化完成工具被权限门禁拦截；损坏协议 JSON 可能进入展示。
5. A2A 只保留消息 DataPart，漏读产物 DataPart；较早的交接可能遮蔽最终交接。
6. 结果验收通过被误当作当前需求覆盖；逐 ID 同步查询造成大量往返；同正文但新私有状态需独立回读身份。
7. 后台仅搬入串行 outbox 仍阻塞根循环；长任务租约、观察者异常和快速任务多余写入均需处理。已恢复的历史错误不再阻断退出；未恢复错误不妨碍其余关闭流程。
8. 进化只选最近成功经验；无效模型响应和恢复中断成本漏计；已知 Token 时忽略调用数。
9. 同版本去重不能封死显式重试；恢复代次与当前 owner 区分重复投递，旧结论不得抢跑问卷、恢复或完成反馈。首次 history 保留，current 可以经显式重试更新。
10. 原生空白结构化正文不得丢弃 SDK 有效正文；A2A 已完成但尚未记录 WorkResult 的崩溃窗口，通过只读 Task 恢复产物，不重复派发。
11. 全局紧急停止同时取消在途记忆推理并停止领取新刷新，取消不推进覆盖、不覆盖有效摘要，持久队列留待重启。
12. Pi 执行侧及只取目录的验收侧仍会无条件构建全量证据文件；分别改为有界候选与绑定作用域的分页读取、跳过证据构建。原生及 A2A 的完整包交付保持兼容。

## 实际限制

首次恢复仍加载本会话归档，首次历史视图仍需一次序列化；暖保存仍比较历史引用，但不重复序列化或重写旧归档。旧数字索引游标走兼容路径；正常调用采用有界新游标。COUNT 和候选筛选仍可能扫描历史元数据，有界返回不代表数据库 CPU 为常数。原生与 A2A 为保留完整证据可达性，仍构建完整交付包，其读取成本随历史增长；Pi 的显式引用和依赖成本随相关证据量增长。旧账本裁剪前的累计次数不可重建。记忆刷新在启动时让行，普通前台任务可以与已启动刷新并行；正常关闭等待在途刷新收敛，紧急停止取消刷新并保留队列，本进程不重新领取记忆刷新，重启后恢复。性能证据来自合成规模、调用次数和真实 CLI 回环，不承诺供应商响应时间或任意复杂目标固定耗时。
