# Pi 会话重构的功能兼容性回溯

日期：2026-11-17。状态：审查后已继续实施，以下表格保留暂停时发现的问题；当前实现和验收见[验证记录](pi-session-ownership-validation.md)。现有改动未提交、未发布；迁移只在临时测试数据库执行，未操作真实用户数据。

## 本次执行的处理结果

已实现执行段/自动交接、可编辑比例、官方并行基线、可选 Work 元信息、只读产物归属修复、原始历史读取及子结果等待。交接采用无损序列化，不增加强制总结请求；缓存预热保持 off。主 Joi 的 user_ask 与 turn_complete 经失败回归后局部使用官方 sequential，独立查询仍并行。迁移按 spec 的保守策略保留源数据并阻止旧程序直接接续新格式；没有承诺旧版直接读写升级后同一库，也未把未回答的降级问题记为用户已确认。

非合作 provider 的取消收尾仍遵循 SDK；未做新的宿主逐工具超时。真实供应商、真实用户库和跨平台发布需要独立验证。

## 用户已明确的修订

1. 一条业务对话可以由多个搭档接续，不与单个 Pi session 一一绑定。连续使用同一搭档可复用当前会话；切换搭档自动 handoff。
2. A→B→A 创建 A1→B1→A2；A2 获取截至当前的 handoff，不恢复缺少 B1 进展的 A1。
3. 压缩由 Pi 执行，压缩触发比例仍可配置。将旧百分比改为只读并忽略其执行效果的处理需要撤回。
4. 工具按官方并行机制作为默认，实际出现具体问题后再微调；不因兼容旧串行实现而统一强制串行。本项不涉及 SDK 依赖升级。

## 源码确认与影响

| 功能 | 当前重构状态与影响 | 修订方向 |
|---|---|---|
| 同搭档多轮对话 | 每轮重建 AgentSession 对象，但用 conversationId 选同一份原生历史。这不等于每条消息都有独立持久会话。 | 业务 conversation 下维护执行段；同搭档连续轮次复用当前段的官方历史。 |
| 换搭档及 A→B→A | 目前仅换提示词、模型和工具，Pi 原生历史身份没有搭档切换边界，未实现自动 handoff。 | 新建后继执行段和官方会话，保存交接链与幂等切换事实。当前实现不满足新增 PI-SESSION-21。 |
| 跨 Pi / Codex / Claude | 当前桥接保留旧 Pi 引用，并把其他引擎消息作为原历史后缀导入；单个原生历史分支会与多个搭档身份混用。存在导入前缀不一致或交接不完整风险，未证明完整往返正确。 | 每段由各引擎的官方会话管理；跨段使用业务 handoff 和来源引用，不继续拼接同一个 Pi 文件。 |
| 压缩比例 | UI 已改为只读，运行时未使用 resolver 返回的旧比例。这是功能退化。 | 恢复编辑和持久化，将触发比例映射公开 reserveTokens 设置，摘要、切点、恢复仍由 SDK 管理。 |
| Work 结构化交付 | 已移除强制 partner_complete，但同时把 Pi handoffStatus 固定为 MISSING，丢失可选结构化交付的产生能力。 | 保留可选的结论、需求/证据/产物引用、未解事项和冲突；普通最终正文仍能完成，不为缺少元信息强制再跑一轮。具体载体须在实施前定稿。此项 Work 交付元信息与普通对话的跨搭档 handoff 分别验收。 |
| 工具顺序 | 旧 Pi 搭档显式串行；官方 Agent 默认 parallel。当前重构中主 Joi 工具仍全部显式 sequential，搭档使用官方默认。 | 用户已决定以官方并行为基线；主 Joi 的统一 sequential 也纳入调整。仅对回归复现的具体冲突，通过公开工具声明局部微调；业务事务、依赖和结果归属继续验收，不另建工具调度器或覆盖 Agent 回调。 |
| 缓存预热 | 旧接线显式 off，新接线使用官方默认；锁定版本默认 idle，可能增加后台请求和用量，部分运行时又在回合结束释放对象。 | 建议兼容旧行为，保持 off，用户显式启用后交给 SDK，并补启用后的生命周期和用量验证；不能把官方默认变化当作用户已选择。 |
| 重试与业务计数 | 新接线恢复 SDK 的 provider/agent 重试，旧的宿主三次预算及 provider 零重试不再控制它。 | 保留已确定的官方恢复方向；一次 SDK 内部恢复仍只对应一个业务 attempt。最终失败分类与所有尝试用量单独验收。 |
| 停止与关闭 | 用户取消通过 SDK abort，已移除宿主逐工具超时和固定强制收尾。合作式取消合成回归通过；不响应取消的 provider 的实际停止延迟未验证。 | 停止请求、界面响应、执行收尾和资源释放分别定义边界，不因为取消等待而复用仍在运行的会话；补异常 provider 与关闭验证。 |
| 结果和产物归属 | settled 后持久结果及孤儿补交已经有回归；新增回归发现只读执行可能把同时出现的其他文件差异当作自己的交付。 | 此项属于既有 AC-WR-06，不需要改产品含义；失败回归已补，因实施暂停尚未修复。 |
| 用量与统计 | 已使用原生条目稳定身份和原发生时间，支持故障补采；新增交接产生的模型调用尚未定义完整身份与归属。 | 为交接生成独立稳定调用身份；旧段已计费用量不随 handoff 再计，新的摘要生成计实际消耗，业务成功次数不增加。 |
| 升级与降级 | canonical 导入、源备份、指纹冲突和消息原子导入已有合成验证。migration 100 改名三张共享会话投影表，使旧读者失败，也影响原生引擎在旧程序下的历史读取。 | 新的多执行段迁移尚未完成；降级策略需决定后再定稿，不能将读表报错等同于清晰的兼容性体验。原生文件和已结算事实必须保留。 |

## 官方接口核对

锁定 Pi 1.5.2 的 [compaction 文档](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/compaction.md) 和本地 `shouldCompact` 实现一致：`contextTokens > contextWindow - reserveTokens`。例如声明窗口 1,000,000、触发比例 80%，传入 reserveTokens=200,000；SDK 决定实际触发、生成摘要及持久化。keepRecentTokens 是另一设置，不能把 80% 解释成压缩后保留 80%。

官方 [handoff 示例](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/examples/extensions/handoff.ts) 使用当前分支的有效上下文生成交接提示，并创建带 parentSession 的新会话。它是交互式示例，需要接到 Joi 的搭档切换与持久事务；不存在“只按 conversationId 保存一个 SessionManager，SDK 就自动理解 Joi 搭档切换”的现成功能。

官方 [settings 文档](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/settings.md) 及锁定包默认值确认 cacheWarming=idle。工具并发默认值也已核对本地固定 Agent 实现。两项均需要显式处理兼容性。

用户随后明确选择官方并行基线。[固定版本 Agent 源码](https://github.com/earendil-works/pi/blob/v1.5.2/packages/agent/src/agent.ts) 与本轮读取的[官方 main 源码](https://github.com/earendil-works/pi/blob/main/packages/agent/src/agent.ts) 均以 parallel 为默认；继续用固定版本验收，不将“按官方最新并行机制”解释为未经要求升级依赖。

## 修订后的交付门禁

- 先确定剩余兼容性决定，并将其写入 spec；当前 PI-SESSION-21–23 是新增门禁，不是完成声明。
- 必须补真实锁定 SDK + 临时原生会话的 A1→B1→A2、跨引擎往返、切换失败、切换重启和用量回归。仅验证提示词换了或 messages 字符串包含旧内容不足以通过。
- 压缩配置验证 UI 提交、持久化、旧值继承和真实自动触发；同时证明没有自管摘要/截断器参与。
- 工具并行验证实际执行重叠、结果身份和失败归属；主 Joi 的具体业务冲突以失败回归为依据，仅做必要的公开工具配置微调。
- 此前通过的 273 项执行/存储回归及调用方回归仅证明各自覆盖场景。新交接与配置修订尚未完成，不能据此宣称整个重构通过。
