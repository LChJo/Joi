# Pi 原生会话托管与搭档结果结算重构 Spec

日期：2026-11-17。状态：**已实施并完成本地范围验收；未提交、未发布**。普通对话包含多个执行段，切换搭档自动 handoff；A→B→A 创建 A1→B1→A2，压缩触发比例继续可配置，工具采用官方并行默认。兼容性回溯见[影响审查](pi-session-ownership-impact-review.md)，实施与验收映射见[验证记录](pi-session-ownership-validation.md)。产品方向仍是 Joi 关注流程和结果，Pi 负责单个执行；工作台注入上下文，搭档扩展技能和工具，优先复用成熟方案。

依据：[桌面项目调研](pi-desktop-session-research.md)、[当前接入审计](pi-sdk-integration-audit.md)、[拟议 ADR 0035](adr/0035-sdk-owned-pi-sessions.md)。旧 ADR 与验收继续描述当前实现；本 spec 的替代规则只在对应实现及回归通过后生效。

## 1. 问题与目标

当前 Joi 同时维护 Pi 会话包装、发送侧摘要/截断、Agent 钩子、工具级暂停与恢复以及最终结果投影。这使 SDK 已有的执行语义与宿主策略交叉，定位失败时难以区分 Pi 行为、展示故障和 Joi 接入策略。长任务中，工具仍活动不能证明业务推进，缺少正文也不能自动证明执行失败。

目标是以官方 Pi Session 为唯一执行上下文权威，Joi 围绕它调度、观察并可靠结算。完成标准首先是：搭档执行和 SDK 语义保持一致；最终交付、失败、取消、未知效果和用量正确归属，且只入账一次。工具次数降低或特定模型一定收敛不作为本重构的保证。

## 2. 范围与用户故事

覆盖普通对话、工作台 Work 的临时/常驻 Pi 搭档、已有子搭档，以及主 Joi 自身的 Pi 推理会话。主 Joi 的目标、DAG、事件优先级、调度、验收、改派和 outbox 业务仍由现有 application/domain 管理。主 Joi 只能使用受支持的业务工具，不因此获得文件或 Shell 能力。

1. 作为用户，我希望长任务使用 Pi 成熟的历史与自动压缩，不因 Joi 的自定义摘要长度规则反复丢失上下文。
2. 作为用户，我希望选择工作台提供本次任务的背景与工程归属，不切换为另一套 Pi 执行算法。
3. 作为用户，我希望搭档配置决定其技能、工具及资源，并在开始执行时固定生效。
4. 作为用户，我希望 Pi 的工具、恢复、扩展和结束逻辑保持官方语义，桌面状态展示不会改写执行。
5. 作为用户，我希望后台执行和页面切换互不影响，事件重复或连接恢复也不会重做工具。
6. 作为用户，我希望自动恢复中的失败尝试不会提前被统计为一次 Work 失败。
7. 作为用户，我希望只在 SDK 真正结算后看到搭档结果，并区分执行结束与业务验收完成。
8. 作为用户，我希望没有正文但产生有效产物的任务也能按验收要求处理，空交付不会被伪装成成功。
9. 作为用户，我希望取消、崩溃和未知效果保留已有输出，不自动重放外部动作。
10. 作为用户，我希望压缩、失败尝试和子任务的真实用量都被统计，历史导入不被重复计费。
11. 作为用户，我希望普通统计或界面写入失败不打断搭档执行，并能发现统计不完整。
12. 作为用户，我希望重启后恢复官方会话的分支和身份，不被导入为一段失去工具关系的聊天摘要。
13. 作为用户，我希望工作台之间的会话、私有上下文和结果继续隔离，即使它们选择同一物理目录。
14. 作为用户，我希望并发协调发生在任务启动前，不在首次工具调用时中断搭档内部过程。
15. 作为维护者，我希望升级 Pi 时以公开接口及真实 SDK 行为回归验证接入，而不是维护一套私有循环。

### 3.1 官方工厂与单一会话权威

使用固定 Pi 1.5.2 的官方会话工厂；有明确 cwd 生命周期替换需求时使用官方 session runtime。由基础设施中的一个会话适配组件集中创建、恢复、订阅、取消、读取结果与释放，不向 application 暴露 SDK 对象。继续使用既有后台运行时，不为采用桌面参考项目而引入第二套 UI 或服务。

普通对话是业务历史容器，在其下保存有序执行段及各自的官方会话引用，不能用 conversationId 固定唯一 Pi session，也不为每条用户消息无条件新建 session。同一搭档的连续轮次复用当前执行段；切换搭档或执行引擎时，在已结算边界自动生成 handoff，创建后继执行段，保留前驱引用。A→B→A 创建 A1→B1→A2，A2 承接截至当前的上下文，不重新激活缺少 B1 进展的 A1。仅换同一搭档的模型/网络优先使用官方模型切换语义，是否有其他配置变更需要新段应在兼容性审查中明确。工作台搭档按 workbench、partner revision 和 instance 隔离，常驻实例串行接收 Work；临时实例和子搭档也走同一官方工厂。主 Joi 自己的推理会话是另一角色、另一会话，保持唯一调度者，不与搭档共享历史。

Handoff 属于搭档切换的主流程。复用固定 SDK 的上下文序列化、新会话与 parent-session 能力，参考官方 handoff 示例；不覆盖压缩器或在旧 Agent 的工具回合内强制追加总结。交接包含当前用户意图、已经确认的结论和决策、未完成事项、产物与附件引用、失败/取消及未知效果，并保留可按权限读取的来源引用。旧工具调用只作事实引用，不成为新会话待执行动作。交接事实、前驱/后继身份及切换提交需幂等；重启或重试不创建重复段、不重复计费。交接失败保留前驱和原始历史，不静默开始空白接续。Pi、Codex、Claude 之间的切换使用相同业务交接契约，各引擎继续管理自己的原生会话。

原生有效上下文已经包含工具交换，业务事实附录不重复附带 TOOL_CALL/TOOL_RESULT 展示记录，也不包含 ACTIVITY 界面活动；正文、错误、产物及附件引用继续保留。已生成的旧交接只对可识别的导入种子修正重复展示投影，通过官方 context edit 保留原始事实；此项数据修复不生成摘要，不按字符预算裁剪原生历史，也不改写普通用户消息。

连续切换时，从可识别的上次交接种子提取有效上下文，与当前执行段的消息合并，再附一份截至当前的业务事实。交接仍使用同一对话内的私有历史引用读取原始条目。

官方 SessionManager 的原生私有会话文件及活动叶节点是 Pi 历史权威。SQLite 保存业务身份映射、会话引用、结果、投影和采集游标；不再把另一份 messages 数组、宿主 checkpoint 或重建投影作为发送权威。索引、缓存及公开历史可从原生事实重建，不能反向覆盖原生事实。

本次交接采用官方 `serializeConversation` 对有效上下文做无损文本序列化，并附业务轮次、状态、附件及产物事实；不额外调用模型生成摘要。各段原始条目通过当前对话范围内的历史工具读取。搭档 revision、技能、扩展或子搭档能力选择改变时创建新段；仅模型/网络改变保留当前段，由新执行边界的官方会话装配生效。切换事务以当前 turn 和前驱段做幂等绑定及并发校验。子搭档使用独立执行身份。

### 3.2 压缩、恢复与资源注入

所有纳入范围的 Pi 会话使用 SDK 自动压缩与恢复。移除 Joi 的发送侧摘要候选、8,000 字符硬接收上限、后台摘要调度、摘要退避、宿主检查点和历史截断路径，不以改名包装的方式保留同类功能。

配置界面保留可编辑的压缩触发比例及已有配置值，明确其含义为“上下文占用达到多少比例时自动压缩”，不表示摘要的压缩率或压缩后的保留比例。固定 Pi 1.5.2 通过公开 `compaction.reserveTokens` / `compaction.modelOverrides` 表达阈值：窗口为 W、比例为 p 时，保留额度为 `W - floor(W * p / 100)`，使 SDK 按 `contextTokens > W - reserveTokens` 自主判断。未配置时使用官方默认。`keepRecentTokens` 保持官方默认，除非另有明确用户设置。UI、持久化和实际 SDK 请求采用同一冻结的模型窗口及比例，不静默忽略旧配置；设置在下一执行边界生效，活跃压缩保持 SDK 捕获的设置。模型能力声明和输出设置通过公开模型配置提供，不在每次请求前自行裁剪输入或重写上游摘要额度。

工作台在 Agent 能力配置层只提供任务背景与提示词；既有工程绑定和结果归属保持不变。工程已有项目指令通过官方上下文资源进入，会话中途不会因为 UI 工作台选择而换 cwd。Partner revision 负责选定技能和工具，第三方能力通过官方资源与扩展入口接入。新 revision 在下一次明确会话创建/切换时生效，不热改活跃执行。

Joi 与搭档继续通过 `DefaultResourceLoader.systemPrompt` 提供各自角色和业务指令。共享装配使用公开 `before_agent_start.systemPromptOptions.sections` 生成 tools、rules、workbench_context 与 system_date；不覆盖底层 Agent 回调。tools 来自当前允许且公开的启用集合，优先使用官方 promptSnippet；rules 合并对应工具的官方 promptGuidelines、补充规则和简短沟通要求并去重。普通对话不再重复列举工具或禁止简述执行思路；主 Joi 的派发、需求与验收约束继续保留。

搭档的项目指令、所选技能及 cwd 由官方资源加载器和提示构建器注入，存在资源时分别生成 project_context、skills 和 cwd，不另复制原文。主 Joi 的已选技能元数据通过独立 skills 段注入，保持 joi_read_skill 的权限边界。工作台背景与角色指令分开。系统日期按宿主时区生成，同时声明时区，在每次新请求开始时刷新；不使用提示中的日期替代真实状态或外部时效核验。

必要业务信息以任务提示、引用或受支持的业务读取工具提供；SDK 负责如何压缩历史。不得为了“保护某段提示”重新实现宿主截断/拼接。安全提示不包含凭据；私有正文不进入日志、统计或共享 DTO。

### 3.3 运行中观察保持非阻断

移除直接设置 Agent 的 before/afterToolCall、prepareRequest、transformContext、finishTurn 等接线。工具授权集合在创建前确定，官方扩展可正常提供其声明的功能；观察用扩展不改变输入、结果或继续/结束决定。

工具执行以官方并行机制为默认，复用上游调度、工具声明和事件语义。主 Joi 与搭档均不能仅因旧实现采用串行，就对全部工具统一声明 sequential。先按官方默认验证实际行为；具体工具出现可复现的顺序或并发冲突时，再使用官方支持的工具执行声明做局部调整，并以对应回归证明调整范围。业务依赖、事务幂等和资源准入继续由既有领域/应用规则保障，不另建宿主工具调度器，也不覆盖 Agent 钩子。此次决定不升级锁定的 Pi 1.5.2。

已复现的局部例外是主 Joi 的 `user_ask` 与 `turn_complete`：同批后续工具不得越过问题或收尾提交，两者使用官方 sequential 声明，其他工具保持默认。主 Joi 的验收参数修正次数仍属于其业务流程门禁。缓存预热保留升级前的 off；显式启用时才使用 SDK 预热及用量事实。

状态与用量订阅只把事件送入有界投影队列，不等待 UI、SSE、统计数据库或展示存储成功。高频增量允许合并；终态和用量通过原生会话及持久游标追平，不能以丢弃后伪造完成解决队列压力。消费者故障使相应投影退化，不通过抛错终止 Pi。

删除宿主按工具次数、文件是否变化、无正文时间进行的 nudge/abort、逐工具超时包装、强制补正文与强制 partner_complete 结束协议。SDK 自身的网络恢复、超时和明确配置的工具行为继续按官方机制执行。用户明确启用的安全扩展属于搭档能力配置，不能拿它实现隐蔽的业务暂停/租约升级。

允许 Joi 发出的执行控制只有明确用户/业务取消、会话生命周期关闭，以及新 Work 的准入与启动。暂停页面轮询、统计写入失败或观察“没有文件变化”均不构成取消授权。

### 3.4 资源协调前移

工作台 Work 在启动官方会话前取得本次已授权完整工具集合所需的资源。只读 Work 只装配读取能力；允许 Shell/写入的 Work 根据既有实际物理目录申请写准入。父子目录按重叠范围协调，兄弟目录互不阻塞。读写请求共用登记顺序，连续读请求可并行，后到写者等待更早的读请求；暂停、容量等待与终态任务让出队列位置，恢复后重新登记。释放或队首退出唤醒已有 outbox 派发，保留周期恢复扫描。

同一读所有者重复准入复用代次，NONE 请求不创建目录租约。引擎停止确认、产物采集、目录验收及不可变结果提交完成后释放租约；后续展示或通知失败可独立重试。取消信号发出后仍需等待引擎停止，迟到收尾按租约代次释放。自由 Shell 或构建仍可能访问整个执行根目录，准入范围由实际工具边界决定。

Pi 不再采用 READ 工具运行后在第一次 Shell/写操作前 abort、保存 checkpoint、再以 WRITE continuation 重启的协议。需要更高能力时由主 Joi 创建符合现有授权的后续 Work，不通过运行中修改工具集合来升级。必要取舍是共享物理目录的写能力 Work 可能更早串行化；独立目录或已明确选择的 worktree 仍可并发。

普通对话沿用 CHAT-15 的并发例外，本重构不为其新增自主任务租约。原生 Claude/Codex 的现有授权与运行协议不在本次重构范围内。

## 4. 结算与结果正确性

业务运行身份在模型请求之前由稳定 Work/run/attempt/instance 和 SDK session 身份绑定。SDK 内部重试、工具轮次、压缩及队列处理不产生新的 Work attempt，也不提前增加业务失败/成功次数。

| 观察到的事实 | Joi 行为 |
|---|---|
| message/tool/压缩/重试事件 | 更新活动投影与原生事实采集进度，不提交 WorkResult |
| agent_end | 暂存尝试结果；可能仍有恢复/队列，不认定最终完成 |
| agent_settled 且官方 prompt/idle 边界已收尾 | 冻结该运行的结果候选，进入唯一业务结算 |
| 明确取消 | 通过官方 abort 等待结束；保留已完成事实，不计成功 |
| 引擎/进程退出，缺少可信 settled 事实 | 按失败或效果未知归档；进程退出码和一段正文不能单独证明成功 |
| 结果或事件迟到 | 根据运行代次和现有取消规则归档，不复活旧 Work，不覆盖新结果 |

正常 SDK 最终正文与有效产物构成交付候选，不要求再调用 Joi 自定义结束工具。结构化 handoff 若缺失，由主 Joi 在结果边界识别缺口，不能在搭档回合内强制追加一轮模型调用。有效产物可在没有正文时通过既有任务验收；正文和产物都不可用时保留真实结束原因并标为交付失败，不伪造成功报告。无需为此新增业务终态枚举，可增加稳定安全原因码。

交付正文取本次执行最后一条 user/toolResult 之后的有效 assistant 文本；工具前的公开进展通过消息事件与原生历史保留，不拼入 WorkResult.body，不将进展文字当作缺失最终交付的替代品。

Work 可通过可选的 `work_handoff` 工具记录已有 WorkHandoff 元信息。该工具不终止执行、不强制使用、不替代最终交付或验收，私有结论不进入活动摘要。`subagent` 工具等待其已准入子任务结算后返回结果，模型按正常工具循环生成父结论；不在父回合结束后强行追加模型请求。

执行已结算不等于业务已通过。沿用 WorkResult 的 verification、需求和证据检查；工作台目标完成仍等待已有综合/评审/收口条件。结果事务顺序保持：不可变结果事实及受限交付 → Work/attempt 状态 → 业务投影与持久事件；提交后再通知、唤醒主 Joi。结果身份幂等，重复 settled、重连或补扫只补缺失投影。

SDK 原生会话已结束但业务结果写入失败时，保留“待提交结果”状态和稳定身份，在不重新调用模型的情况下重试提交。崩溃前没有持久可信 settled 事实时，不仅凭最后一条 assistant 推断成功；按现有中断/未知效果恢复规则处理。

普通对话启动恢复按工作台、对话、执行段和轮次读取已持久化的 Pi 结果，补写安全正文、产物和轮次状态。缺少可信结果的运行中轮次保留为中断。

## 5. 结果统计与用量统计

两套统计分开：业务计数来自最终结果事务；token 等用量来自 SDK 的供应商数值事实。不能用工具完成数、正文出现、inbox 状态或 SDK 中间 agent_end 推断业务成功。

用量采集覆盖 assistant 回复、失败/取消前已报告用量、独立 usage entry、compaction、branch summary，以及 SDK 启用时的 cache warming。子搭档单独归属并与父 Work 建立关联，父总览不能重复加一次子用量。未知值保持未知。

优先以 SDK 会话身份、规范条目身份和用量槽位去重，绑定当时的 Work/run/attempt/model revision。会话累计快照只作对账或按稳定调用身份替换，不能把整个常驻会话累计量再次记入每个 Work。压缩后不删除历史消耗；分支/导入/迁移形成的新会话，从明确基线开始采集，不追补已归档旧历史。没有活动 Work 的后台用量归为独立已定义用途，不能随意记到最后一个 Work。

继续遵守 AC-STATS 的口径：输入包含缓存，输出包含推理，细分不再加一次；无费用估算、无外部遥测、无解析私有正文补数。与 SDK 总量核对时先统一缓存分类口径。

普通统计落库失败不改变执行结果；记录可见的采集异常，按游标从原生记录补采。原生权威存储自身失败属于 SDK/引擎故障，应按真实错误结算，不能以“观察非阻断”掩盖不可持久执行。

补采游标以会话身份、已确认连续条目位置及归属上下文持久保存，只有统计写入确认后才能越过用量条目。重启复用已确认进度；文件大小与修改/变更时间均未变化、已追平且最后确认用量仍存在于统计账本时，原生历史不再读取或重放。新增条目继承原用途与 Work 边界；游标损坏时记录降级并按稳定用量身份重建。统计数据库单独回退或重建导致确认事实不存在时自动重扫，不猜测成功、不要求用户手工清游标，也不重新执行模型。

## 6. 迁移与兼容

迁移覆盖 Pi 搭档和主 Joi 的既有私有历史。保留原始数据只读备份，不读取真实数据做自动化测试，不把发布启动变成重新执行旧任务。

| 既有数据 | 迁移规则 |
|---|---|
| 版本化 Pi header、entries、parent/leaf、context edits | 通过固定 SDK 支持的导入/恢复能力保持身份与活动分支；导入后用 SDK 投影对照验证 |
| 只有私有 messages 的旧会话 | 使用一次性、可审计导入；保留实际可用事实和来源缺失标志，不编造丢失工具结果 |
| Joi checkpoint、summaryRetry、自定义摘要投影 | 作为旧实现审计数据保留，不参与新运行的压缩或发送投影。检查点消息需要匹配完整旧格式，普通消息中引用标记不影响恢复 |
| 旧 RUNNING/SUSPENDED、未配对工具或未知效果 | 明确中断/未知事实，不自动恢复 pending 工具，不把新任务许可解释为旧动作重放授权 |
| 已完成 WorkResult、统计账本、原生 Codex/Claude 会话 | 保留事实与口径，不因 Pi 迁移重新计数或改写 |

每个旧会话有稳定迁移身份、来源指纹、目标会话引用及完成状态；重跑迁移复用结果，不复制第二份历史或再计用量。源数据不兼容时保留可阅读历史并给出稳定迁移失败事实，禁止静默创建空白会话冒充恢复成功。公开共享协议不传原生文件路径或私有条目。

旧快照只有 piSession、尚无 piNativeSession 时，handoff 读取其有效上下文作文本导入并保存业务 predecessor；当前不为它虚构官方 parentSession 文件引用。已有原生源文件及有效引用时才建立官方 parentSession；两种路径均保留源事实与业务交接链。

切换采用运行时停机/排空边界，不能把正在运行的旧 Agent 原位替换为新 Session。回滚前的新增官方会话文件与业务结果必须可继续保留；兼容性检查未通过时禁止旧版本自动接续新格式。迁移和回滚只操作拥有明确身份的对象，不做按目录猜测的清理。

迁移 100 将三张共享会话表改名为投影，保留数据并阻止旧读者把新投影当执行权威；迁移 101 新增对话执行段和 turn 绑定。旧表、源 JSON 备份及原生文件均保留。该实现不提供旧版程序直接读写升级后同一数据库的兼容承诺；回退需要升级前备份，不能只覆盖程序文件。迁移尚未对真实用户数据执行。

## 7. 验收标准

以下为实施门禁，具体通过范围与限制以验证记录为准。

| 编号 | 可观察的通过条件 |
|---|---|
| PI-SESSION-01 | 四类搭档执行入口和主 Joi 的 Pi 推理使用官方工厂/会话；真实 SDK 合成 provider 下的工具、资源与消息转换可用 |
| PI-SESSION-02 | 自动压缩由 SDK 触发、持久化并在后续请求/重启中生效；没有 Joi 摘要、字符拒收或截断投影参与 |
| PI-SESSION-03 | 通过官方扩展触发工具钩子、上下文和 turn 边界行为，实际请求与继续/结束决策保持上游语义 |
| PI-SESSION-04 | 工作台只贡献上下文和既有工程归属；Partner revision 决定技能/工具，活跃会话不被热改；官方工具元数据保留到实际 tools/rules 段；项目指令、所选技能和 cwd 不重复，停用工具不残留说明，系统日期按时区随新请求刷新 |
| PI-SESSION-05 | 原生 SessionManager 是唯一历史权威；SQLite 投影损坏不反向覆盖原生分支/条目 |
| PI-SESSION-06 | UI、SSE、统计和普通投影回调故障不阻止工具/下一模型轮次；恢复后可追平并显示采集异常 |
| PI-SESSION-07 | 持续只读或仅调用工具的合成执行不被宿主次数、文件变化、正文规则中断，也没有强制 partner_complete |
| PI-SESSION-08 | Work 的 Pi 资源在启动前准入；等待不计运行，无中途 READ/WRITE abort/resume；普通对话保持 CHAT-15 |
| PI-SESSION-09 | 多次 agent_end/重试/压缩只对应一个业务 attempt；settled 前不发布终态结果或增加完成/失败次数 |
| PI-SESSION-10 | settled、prompt/idle 和业务结果事务形成明确边界；重复事件、重复提交和重连只归档一次 |
| PI-SESSION-11 | 取消、最终失败、空交付、有效产物无正文和成功正文分别映射真实结果；业务验收与 SDK 结束独立 |
| PI-SESSION-12 | 提交前崩溃、提交后通知前崩溃、结果写入失败重试均不重做模型或外部工具；无可信 settled 不推断成功 |
| PI-SESSION-13 | assistant、独立 usage、失败尝试、压缩、分支摘要及启用的后台用量与 SDK 事实对账，归一化后不重复累计 |
| PI-SESSION-14 | 常驻会话跨两个 Work、子搭档、历史导入和重复 usage 事件归属正确；未知数据不估算补数 |
| PI-SESSION-15 | 统计故障不改业务终态，补采幂等且可见；持久游标只越过已确认用量，重启不重写旧条目，未变化且已追平的历史不再整段读取；Work/目标计数由原有结果/收口事实驱动 |
| PI-SESSION-16 | 迁移保留 canonical entry/parent/leaf/context-edit 身份；旧不完整工具交换不被执行，迁移重跑无重复 |
| PI-SESSION-17 | 工作台/搭档/会话隔离、迟到事件代次门禁和取消后归档规则成立，不因共享物理目录跨上下文 |
| PI-SESSION-18 | 主 Joi 的计划、Work DAG、唯一调度、综合验收、outbox 和幂等语义保持；其 Pi 会话压缩也已交接 |
| PI-SESSION-19 | Codex/Claude/A2A 已有契约及桌面/远程 DTO 继续工作；Pi 私有会话、凭据和正文不进入诊断 |
| PI-SESSION-20 | 所有活跃自管压缩、底层钩子覆盖、工具级资源暂停及重复会话权威路径被删除；文档不再声称运行使用旧策略 |
| PI-SESSION-21 | 同一搭档多轮复用当前段；A→B→A 自动形成 A1→B1→A2 并继承截至当前的有效上下文；跨 Pi/Codex/Claude、交接失败、重启及重复切换不丢事实、不重放动作、不重复创建或计费 |
| PI-SESSION-22 | 旧、新压缩比例均可编辑并持久化；按冻结模型窗口映射公开 SDK token 设置，真实自动压缩验证触发点；默认值及模型切换生效范围明确，Joi 不执行自己的摘要/截断算法 |
| PI-SESSION-23 | 对旧功能逐项审查会话接续、可选 Work 交付元信息、工具执行顺序、缓存预热、停止/关闭、投影故障、归属和迁移/回滚；未决行为先讨论并修订 spec，不能用删除原验收替代兼容性证明 |
| PI-SESSION-24 | 工具采用官方并行默认，独立调用可实际重叠执行；并行成功/失败的结果、事件与用量仍关联正确身份，主 Joi 的事务与依赖不变量成立；仅对已复现的具体冲突使用公开工具声明微调，不统一强制串行或另建调度循环 |

## 8. 测试决定与验证范围

优先在既有 PartnerEngineRuntime、PrimaryReasoningRuntime 和结果提交端口验证外部行为。使用真实锁定 SDK、合成 provider、临时原生会话与 SQLite、凭据替身；测试完整工具/恢复/压缩/结算时间线，不用断言包装函数调用次数代替正确性。

复用现有会话契约、普通对话执行、搭档实例、WorkResult、统计和工作区协调回归；新增核心场景是官方压缩后的真实请求、扩展决策保真、非阻断投影故障、主 Joi 会话迁移和跨 Work 用量对账。崩溃测试覆盖准入、权威事实和结果事务之间的边界。

实施每个行为阶段先添加并运行失败回归，再改实现。TypeScript 改动运行 typecheck 和定向 lint；模块职责/import 变化运行架构边界检查。SDK 打包或 worker 入口变化才追加相关构建与离线资源验证；Electron 生命周期或实际窗口影响才追加对应 E2E。依据实际 diff 选择范围，通过后停止扩大，不把本 spec 的范围等同于立即运行全仓发布验收。

文档审计与运行验收分别记录；不把早期审计结果替代新架构的行为验证。

## 9. 实施阶段与退出条件

| 阶段 | 交付和退出条件 |
|---|---|
| P0：官方接入与迁移探针 | 固定版本公共 API、原生导入/恢复、资源注入、能力限制、SDK 压缩/usage 和 settled 全链路由合成回归证明；所有临时数据可丢弃 |
| P1：搭档执行收敛到官方 Session | 临时/常驻 Work、普通对话、子搭档统一适配；移除运行中钩子覆盖、补正文/完成协议和工具级暂停；运行前准入与结果结算通过 PI-SESSION-01–12、17 |
| P2：会话存储和用量切换 | 官方历史成为唯一权威，旧数据幂等迁移、崩溃恢复和数值账本对账通过 PI-SESSION-05、12–16；不得将 P1 作为长期双权威交付 |
| P3：主 Joi 交接与旧逻辑删除 | 主 Joi 也使用官方会话/压缩，业务工具及调度验收通过；共享旧压缩器与旧权限暂停路径不再可达 |
| P4：契约、文档和交付验证 | 完成全部 PI-SESSION；按实际影响更新 ADR/CHAT/SUM/WR/统计验收、迁移说明及模型证据，再运行相关构建/桌面检查 |

各阶段可独立实现和验证，但面向用户的完整切换必须等 P0–P4 必要门禁通过，不能在旧新会话之间运行中切换。每阶段保留稳定业务身份和可检验回滚条件，不以完成代码移动作为行为完成。

## 10. 既有规则的替代关系

| 既有约束 | 本 spec 实施后的变化 |
|---|---|
| CHAT-19/20/21、ADR 0033/0034、SUM-01–12 | 保留连续性、隐私、取消与可靠结算目标；原生 Session/压缩替代 Joi 摘要实现及检查点策略 |
| ADR 0022、0025、0031 中 Pi 发送侧预算/锚点实现 | 保留任务信息和证据可达性要求；必要信息走官方资源/业务工具，不另建输入截断器；主 Joi 也纳入迁移 |
| ADR 0023 中基于工作区变化/工具计数的干预 | 删除 Pi 内部 nudge/abort 与强制正文，保留主 Joi 依据最终结果决定后续 Work 的业务能力 |
| ADR 0028、AC-WR 的 Pi 工具级暂停/升级 | 改为 Work 启动前准入和固定能力；原生引擎现有路径及普通对话并发例外保持 |
| ADR 0006 与 AC-14/33/46/53/54/62/67 | 继续要求结果先归档、身份幂等、取消/迟到规则及主流程正确；只替换 Pi 引擎接线 |
| ADR 0021、AC-STATS | 继续使用供应商事实、故障隔离与业务完成口径；补齐 SDK 内部用量和跨 Work 归属 |

## 11. 不在本次范围与已知取舍

不替换 Joi 的领域/应用架构、主调度器、React/Electron 桌面栈或原生/A2A 引擎；不升级模型或 Pi 版本来替代接入验证；不引入第三方桌面项目完整代码、私有 Pi fork、额外审批框架或新一套工具限额。

官方自动压缩不保证所有模型都收敛。更早取得 Work 写准入可能降低同目录并行度；这是避免工具中途暂停的明确取舍。原生文件与业务数据库之间没有跨存储原子事务，必须用稳定引用、游标和结果幂等处理崩溃窗口。真实供应商质量/延迟仍需在实现后另做受控对照，不能由源码调查或本轮文档检查声称通过。
