# 交互与页面规格

## 0. JOI-01 首页与首次连接

首页默认只显示唯一全局 joi 的对话时间线、输入框和当前工作状态。Avatar、搭档、模型源、任务与诊断是按需展开的次级界面；用户无需先创建或打开 Avatar。

不存在 `READY` 模型源时，首页主文案必须精确显示“joi需要链接到大模型网络”，并展示恰好 7 个厂商级入口：Kimi、GLM、Qwen、Doubao、MiniMax、DeepSeek、通用平台。产品界面不出现转发或聚合平台。配置采用“厂商 → 接入方案 → 接口协议”结构：先选择普通 API 或官方 Coding Plan / Token Plan；该方案同时支持两种协议时，再选择 OpenAI-compatible 或 Anthropic-compatible，只支持一种时直接进入表单。

- Kimi、GLM、Qwen、Doubao、MiniMax 分别提供普通 API 与 Coding/Token Plan 二级选项；DeepSeek 当前仅显示 API；通用平台直接进入自定义配置。
- Kimi Code、GLM Coding Plan、Qwen API/Coding Plan、Doubao Coding Plan、MiniMax API/Token Plan 提供 OpenAI-compatible 与 Anthropic-compatible；Kimi API、GLM API、Doubao API、DeepSeek API 仅提供 OpenAI-compatible。
- 官方接入方案仅显示对应 API Key、推荐模型与高级 Model ID；endpoint 由接入方案和协议共同固定且不展示、不编辑，普通 API Key 与套餐 Key 不得混用。
- 已验证为 `READY` 的 API 与 Coding Plan 来源都可成为全局 joi 的主源或备用源；套餐表单明确提示订阅权益通常面向个人交互式使用，用户需遵守厂商条款。
- 通用平台先选择 OpenAI-compatible Chat Completions 或 Anthropic-compatible Messages，再填写显示名称、Base URL、API Key、Model ID；明确不支持 OpenAI Responses；localhost/127.0.0.1 可留空 Key。
- 验证失败时保留草稿、设置和诊断入口，但普通 composer 继续门禁；界面按鉴权、模型不可用、接口不可达给出可操作提示；验证旁提示兜底最小文本请求可能产生极少量费用。
- 普通首页显示“输入已保存、joi 已归类、工作已派发、搭档已接受、结果已整合”等可核验阶段；连续输入无需用户选择串行或并发。

### 0.1 搭档页与搭档配置

搭档页是 joi 的统一搭档目录，以卡片网格展示：每张卡片显示名称、描述、类型与引擎徽标、启用状态、知识库数量，以及复制、编辑、停用、删除操作；由 joi 创建的搭档带“joi 创建”徽标。搭档少于 2 个时，首页与搭档页都提醒用户先建立 2-3 个工作搭档。

添加搭档先选择模式：本地搭档（本机引擎执行）或远端 A2A（通过 Agent Card URL 与 Bearer Token 登记，能力以 Card 为准合并）。本地搭档编辑分为基础与高级两页：

- 基础页：两列对齐布局——名称与工作路径 cwd 同行、描述（给 joi 派发做参考）与搭档提示词同行；工作路径点击"选择目录"由本机原生目录对话框选取（不手填，可清除）；知识库（附加 md 文档，不超过 8 篇、每篇不超过 256 KiB，内容导入本机数据库并随备份恢复）；技能按当前引擎扫描本机已安装技能（`~/.claude/skills` 等）以点选复选框呈现，无手填、无"能力标签"。
- 高级页：搭档引擎三选——Pi core（默认）、Claude Code、Codex；后两者探测用户本机 PATH 上已安装的 CLI（含 codex 原生包与 macOS Codex.app），未检测到时选项标注"未检测到"并在选中后提示，选未检测引擎创建/更新在服务端以 409 门禁拒绝。Pi core 显示模型名（可选覆盖）与供应商下拉，下拉旁"管理大模型网络"按钮跳转到设置页的模型网络管理；Claude Code / Codex 仅显示可选模型名覆盖（留空即用本机 CLI 自身的登录/转发/订阅配置，joi 不注入密钥），并隐藏供应商。工具白名单按所选引擎列出该引擎的原生工具名（不勾选 = 不限制），从基础页移至此页。详见 ADR 0004。

所有修改登记为新的不可变 revision，在途工作按旧 revision 完成（DRAIN）；复制搭档基于活跃 revision 产生独立副本，提示词与知识库另行复制。提示词正文、知识库正文与工作路径仅本机保存，不在列表接口返回；知识库只注入本机引擎的系统提示词，不发给远端 A2A。

下文“全部生命/生命创建向导”描述迁移前界面，只用于旧版本回归；JOI-01 上线后由本节替代。

## 1. 体验目标

用户看到的不是“配置一个复杂工作流”，而是“认识、照料并观察一个持续存在的数字生命”。默认路径必须短：连接 Agent、描述它是谁、点击出生。事件、协议、context 和恢复细节只在需要诊断时出现。

## 2. 信息架构

桌面窗口与局域网浏览器共用以下导航：

```text
joi
├── 生命
│   ├── 全部生命
│   └── 生命详情
│       ├── 活动
│       ├── 事务与待办
│       ├── 记忆
│       ├── 作息与闹钟
│       └── 设置
├── Agents
├── 系统活动
└── 设置
    ├── 局域网访问
    ├── 管理员与会话
    ├── 预算默认值
    ├── 备份与恢复
    └── 诊断
```

默认首页是“全部生命”，而不是系统设置或 Agent 列表。

## 3. 首次设置

### 3.1 步骤一：管理员口令

- 只允许在桌面本机完成首次设置。
- 输入口令与确认口令；不增加用户名、安全问题或邮箱。
- 明示“该口令用于局域网浏览器访问，不会恢复加密的 Agent Token”。
- 完成后自动建立桌面本地会话。

### 3.2 步骤二：局域网访问

- 默认关闭 LAN Listener，桌面功能不受影响。
- 开启时只列出 RFC1918 IPv4；用户选择一个地址，端口默认 `43130`。
- 显示访问 URL、可信局域网 HTTP 风险和“复制地址”。
- 绑定失败时保留桌面可用，并显示明确错误与重试。

### 3.3 步骤三：连接主 Agent

- 两个输入：Agent Card URL、Bearer Token。
- “测试并保存”一次完成 Card 拉取、协议校验、健康检查和 readiness。
- Token 输入完成后不再回显原文；只显示“已保存”和轮换入口。
- readiness 未通过时说明“可作为协作者，但暂不能成为主 Agent”。

用户可跳过 Agent 连接进入空状态，但不能启动生命。

## 4. 生命创建向导

向导只有三个步骤，并支持返回修改：

### 4.1 它是谁

- 必填：名称、人格摘要。
- 可选：头像、角色、原则、初始目标。
- 人格摘要建议 50–500 字；不要求编写 system prompt。

### 4.2 它如何行动

- 选择一个已通过 readiness 的主 Agent。
- 可选协作者，默认全不选。
- 展示主 Agent 与协作者的职责差异，不展示 Token、模型或底层 URL。

### 4.3 它如何生活

- 时区默认系统时区。
- 默认作息：08:00 计划、21:00 复盘、03:00 记忆整理。
- 默认安静时段与预算以摘要卡展示；高级编辑折叠。
- 最终按钮为“让它出生”。点击后原子创建生命与 `system.birth` 事件，并跳转活动页。

## 5. 全部生命页

### 5.1 生命卡片

每张卡只展示：

- 名称、头像、角色摘要。
- 状态：休眠、等待唤醒、运行中、暂停、等待用户、预算暂停或异常。
- 主 Agent 名称和连接健康点。
- 今日自主唤醒与 A2A 调用额度。
- 下一次已知唤醒时间、未读表达数和待处理问题数。

主操作为“打开”；启停开关只在卡片悬浮或更多菜单中出现，避免误触。

### 5.2 空状态

- 没有生命：突出“创建第一个数字生命”。
- 没有可用主 Agent：先引导连接 Agent，保留产品说明。
- Hub 暂停：显示全局横幅和“恢复运行”。

## 6. 生命活动页

### 6.1 页面布局

```text
┌─────────────────────────────────────────────────────────┐
│ 头像 名称  状态  主Agent  今日预算  下一次唤醒  [暂停]    │
├──────────────────────────────┬──────────────────────────┤
│                              │ 当前关注 / 意识残留       │
│ 活动时间线                    │ 活跃事务与待办             │
│ 用户消息 / 生命表达 /         │ 闹钟 / 等待输入             │
│ 系统事件 / Agent 调用         │ Agent 健康与调用            │
│                              │                          │
├──────────────────────────────┴──────────────────────────┤
│ 输入消息…                           [附件] [发送] [停止] │
└─────────────────────────────────────────────────────────┘
```

窄屏浏览器将右栏折叠为“状态”抽屉；时间线和输入框始终优先。

### 6.2 时间线事件样式

| 类型          | 展示原则                                                                  |
| ------------- | ------------------------------------------------------------------------- |
| 用户消息      | 中性表面、主文字色；标记“排队/已读取”；已读取只来自 Turn Injection 事实。 |
| 生命表达      | 独立头像与正文；不拼接“任务完成”等协议状态。                              |
| 系统事件      | 紧凑时间线节点，可展开查看触发原因。                                      |
| 主 Agent 运行 | 展示开始、阶段、耗时与结果摘要；默认折叠技术细节。                        |
| 协作者调用    | 展示 Agent、委派标题、状态和安全结果摘要。                                |
| input/auth    | 高亮操作卡，提供绑定原 interaction 的回答或授权入口。                     |
| Artifact      | 文件卡片显示名称、类型、大小、来源与下载/预览动作。                       |
| 错误          | 给出可理解原因、是否会自动重试、手动操作。                                |

时间线不得显示 thinking、原始 tool payload、Token、绝对路径或完整 A2A payload。

### 6.3 输入框

- Enter 发送，Shift+Enter 换行。
- 发送后立即形成事件，不等待 Agent 接受。
- 生命运行时文案为“消息会在下一轮出现”，不提供破坏式“立即打断”；断线或重启后仍按 eventId 去重显示。
- “停止”仅在存在运行调用时出现；点击后选择“停止本次运行”或“暂停这个生命”。
- MVP 附件限制沿用 A2A 基线：最多 8 个、单个 10 MiB、总计 25 MiB。

## 7. 事务、记忆与作息

### 7.1 事务与待办

- 事务按进行中、等待、完成、失败、取消分组。
- 展示当前负责人、下一步、等待对象、关联 Wake 和协作者。
- 用户可以新增/编辑/完成待办；这些操作均写事件，不直接改 Agent context。
- 允许用户“现在提醒它”，生成高优先级 `todo.reminder`。

### 7.2 记忆

- 三个视图：意识残留、情景记忆、语义记忆。
- 展示来源时间、关联事件/事务、置信度和最后使用时间。
- 用户可以修正或遗忘一条记忆；系统保留修订审计但不再召回旧内容。
- 不显示 embedding、向量距离或数据库概念。

### 7.3 作息与闹钟

- 作息使用简单列表，不使用复杂 cron 编辑器。
- 周期选择仅提供每天、工作日、周末、每周指定日和自定义时间。
- 闹钟显示创建者、触发时间、关联事务和是否允许在安静时段运行。
- 删除或修改重复规则不会删除已经生成的历史事件。

## 8. Agents 页

每张 Agent 卡展示公开 Card 信息、连接健康、主 Agent readiness、正在被哪些生命使用和最近调用状态。

支持：

- 添加：Card URL + Bearer Token。
- 刷新 Card 与重新测试。
- 轮换 Token，不回显旧 Token。
- 停用：停止新调用，不取消已运行调用。
- 删除：必须先解除生命绑定；不声称删除远端 Agent 数据。

Card Origin、协议、transport 或认证发生变化时，卡片进入“需要重新确认”，所有新调用暂停。

## 9. 系统设置与诊断

### 9.1 局域网访问

- LAN 开关、明确 IP、端口、当前 URL、监听状态与错误。
- 不使用 `0.0.0.0`，不自动修改防火墙。

### 9.2 管理员与会话

- 修改口令会撤销所有 LAN 会话，但保留桌面本地会话。
- 展示当前会话设备的时间、IP 摘要和最后活动；允许全部退出。

### 9.3 备份与恢复

- 创建版本化备份、查看最近备份、选择备份恢复。
- 明示备份不包含可在其他机器解密的 Agent Token；恢复后需重新输入 Token。

### 9.4 诊断

- 展示 Runtime、数据库、事件队列、A2A Endpoint 和 Listener 状态。
- 导出默认只含状态、计数、版本和错误码，不含业务正文或地址。

## 10. 状态与反馈

- 用户动作在 300 ms 内给出本地接受反馈。
- 长操作使用阶段状态，不使用无限旋转且无说明的 loading。
- 网络断开时保留本地可读历史；写操作明确显示“未提交”或“已进入本地队列”。
- SSE 重连后以游标补齐缺失事件，避免重复插入。
- 不使用绿色底白字作为普通用户消息或成功状态的默认样式。

## 11. 可访问性与响应式

- 键盘可完成登录、消息发送、暂停、回答 input 和导航。
- 状态不能只依赖颜色，必须包含文字或图标。
- 正文、时间线和表单满足 WCAG AA 对比度。
- Windows 桌面窗口不显示 Electron 默认的 File、Edit、View、Window 原生菜单栏；产品操作保留在应用界面与托盘菜单中。
- 支持桌面窗口最小宽度 960 px；LAN 浏览器最低适配 768 px。
- 所有日期同时提供本地时间，诊断展开区可显示 ISO 时间。

## 12. UX 验收场景

1. 首次设置到生命出生不超过三个主要页面、十分钟。
2. 生命运行中发送消息，时间线立即显示排队且当前调用不被取消。
3. 闹钟触发后能从时间线追溯“谁创建、何时触发、唤醒了哪个 Wake”。
4. 两个协作者并行完成时，用户看到两个独立结果事件和后续主 Agent整合。
5. auth-required 不泄露 Token 给主 Agent，用户可在原卡片处理并恢复。
6. LAN Listener 失败时桌面窗口仍可管理生命。
7. 重启后页面恢复到真实状态，不把未知远端调用显示为失败或完成。
8. Windows 桌面窗口启动后不出现 Electron 默认原生菜单栏，托盘菜单仍可用。
